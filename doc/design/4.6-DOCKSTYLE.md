# dockstyle 收缩为「结构 + 令牌」——路线 A 设计稿

> 状态：**设计稿，待作者确认后再开工**（2026-10-19 起草）。
> 背景：4.6 C1g 之后 dock 表仍在亮暗两套下出问题，作者判定「四张手写表 + 运行时
> `palette()` 近似」这个结构本身已到极限，4.6 台账 K⑥ 已记录结案更正。
> 本稿只回答一件事：**dockstyle 应该控制什么、颜色从哪来**。
> 结论先写在前面：**表的行文留下，表里的颜色值全部换成令牌；令牌由主题给。**

## 一、问题陈述

`res/dockstyle/` 现在有 4 张手写表、1665 行。`default.css` 的 88 条声明里：

| 类别 | 条数 | 例子 | 判据 |
| :--- | ---: | :--- | :--- |
| 颜色 | 46 | `palette(window)`×6、`palette(light)`×4、`palette(dark)`×9 | **不该由它决定** |
| 几何 / 取消绘制 | 42 | `padding`、`border-width`、`qproperty-iconSize`、`background: none` | 该留下 |

46 条颜色里又分两种病灶：

- **用调色板角色近似语义**：`palette(dark)` 是 `window.darker(150)` 的派生值，不是设计意图。
  它同时被用来表示「分隔线」（8 处）和「标签竖线」（`border-color: palette(light)`，1 处）——
  **同一个概念用了两个方向相反的角色**，暗色下一条变近黑、一条变中灰。
- **硬编码色值**：`#ffffff`×3、`rgba(255,255,255,60/92/96)`×5、`rgba(0,0,0,32/48)`×7。
  它们断言「强调面一定深、亮面一定白」，暗色下 tab 字形变黑、侧边条底纹消失，都来自这里。

一句话：**它同时在当「几何契约」和「皮肤」，而皮肤那份是从 QPalette 抄来的二手信息。**

## 二、职责边界（本设计的第一条判据）

| dockstyle 管 | 主题（10 张表 + 调色板）管 |
| :--- | :--- |
| 选择器：类名、动态属性（`activeTab` / `iconOnly` / `sideBarArea` / `focused`）、伪状态（`hover` / `pressed`） | 每个令牌的**具体颜色** |
| 边框在**哪一侧**、几 px、圆角、`padding`、`min-height` | 同一令牌在亮/暗两套下的取值 |
| `qproperty-iconSize` / `qproperty-spacing` / `text-align` | 选中态**形态**（第二阶段，见 §八） |
| `background: none` / `border: none`（把像素还给控件的声明） | — |

判断一条声明归谁，只问一句：**它是不是「qxdock 的部件词汇表」的一部分？**
是（`DockSideTab` 的 4 个方位、`activeTab` 驱动的状态）→ 留；只是某个颜色 → 走令牌。

## 三、令牌清单（15 个）

命名与 `tools/themes/*.css` 的占位符同风格（kebab-case），同一语义的两张表可以用同一个名字。

| 令牌 | 语义 | 现在的写法 | 备注 |
| :--- | :--- | :--- | :--- |
| `surface` | 容器 / 面板 / 标签 / 侧栏 / 缩放手柄的底 | `palette(window)` | 6+9 处 |
| `surface-raised` | 停靠部件内容面 | `palette(light)` | 比 surface 抬起一档 |
| `divider` | 一切 1px/2px 分隔与边（方向由主题决定） | `palette(dark)` + `palette(light)` | **合并两个角色**，见 §一 |
| `text` | 活动标签、正文 | `palette(foreground)` | |
| `muted-text` | 非活动标签 | `palette(placeholder)` | |
| `accent` | 强调填充（焦点标签、autohide 标题栏、活动标记边） | `palette(highlight)` | 9 处 |
| `accent-text` | 压在中性面上的强调色**文字** | `palette(highlight)`（`DockSideTab:hover`） | 与上一个同名角色、不同用途 |
| `on-accent` | 压在强调面上的文字 / 字形 | `#ffffff` | **C++ 侧取 `HighlightedText`**，见 §五 |
| `on-accent-hover` | 强调面上的悬停洗 | `rgba(255,255,255,60)` | |
| `on-accent-pressed` | 强调面上的按下洗 | `rgba(255,255,255,92/96)` | 两档合并（差 4/255，不可见） |
| `subtle` | 面上的低对比底纹（侧边条 6px） | `rgba(0,0,0,48)` | 暗色应反转成白洗，见 `fromPalette` |
| `hover` | 普通面上的悬停填充 | `palette(light)` | |
| `pressed` | 普通面上的按下填充 | `palette(mid)` | |
| `tab-active-top` | 选中标签渐变起点 | `palette(window)` | |
| `tab-active-bottom` | 选中标签渐变终点 | `palette(light)` | |

`DockFloatingTitleBar` 的 `palette(midlight)` 并入 `surface-raised`（同为「比窗口面亮一档」）；
`rgba(0,0,0,24)`（浮动关闭按钮 hover）并入 `hover`。

### 为什么不是「直接用主题的 15 个角色名」

主题的角色名（`surface-alt` / `state-hover` / `accent-fill` / `text-on-fill`…）描述的是
**Ribbon 的层次**，dock 需要的是**它自己的层次**：同一个 `accent-fill` 在 ribbon 里是
「选中页签的底」，在 dock 里是「焦点标签 + autohide 标题栏 + 活动标记」三个位置，将来可能分叉。
所以 dock 有自己的令牌表，**值**由应用从主题的角色表映射过来（唯一对应关系见 §五 第 6 条）；
`DockStyleColors` 是这张表的类型。

## 四、模板与片段：4 份 → 1 份基底 + 2 个开关

现在的 4 份文件不是 4 种外观，是 **1 种外观 ×（focus / 平台）**。它们之间有五处不是「追加」
而是「替换」，直接拼会得到错误结果，必须逐条归一：

| 差异 | 现写法 | 归一为 |
| :--- | :--- | :--- |
| splitter handle 选择器 | focus 版去掉 `DockContainer ` 前缀 | 统一用宽的 `QxDock--DockSplitter::handle` |
| close hover 的 1px 边 | focus 版注释掉 | 统一保留（focus 下多一条 1px 边）—— **有意改变** |
| 标签 iconSize | focus 版加在 `DockTab` 上 | 移入 base（两版都该有 16px）—— **有意改变** |
| `#dockTabsMenuButton::menu-indicator` | linux 版加了 `DockPanel ` 前缀 | 统一用带前缀的（更具体，语义相同） |
| 标签竖线 `border-color` | windows 版 `palette(light)`、与分隔线的 `palette(dark)` 方向相反 | 统一走 `divider`（按明暗翻转）—— **有意改变** |
| autohide 标题栏的 focused 修正 | 位置不同、内容相同 | base 保留一份 |

归一后文件布局：

```
res/dockstyle/base.css    结构 + 几何 + 令牌占位符（含焦点态）
res/dockstyle/x11.css     浮动标题栏 + X11 桌面需要的差异
```

焦点态与其余规则同在 `base.css`：它每一条都要求一个只在 `FocusHighlighting` 打开时才存在的
动态属性（panel/tab 的 `focused`、标题栏的 `focusHighlighting`），故 flag 关时恒不命中，
不需要单独成片（详见 `4.6-TASKS.md` C1j）。`dockStyleSheet()` 读 `base`，X11 构建再追加
`x11`。**占位符未替换即视为构建错误**
（见 §六的验收第 1 条）——静默留一个 `{{divider}}` 在表里，会让那一条声明被 Qt 整条丢弃。

## 五、API（4.6 只做加法）

`qxdock::dockStyleSheet(bool)` 已随 4.5.0 / qxdock 0.3.0 发布，**签名不动**。新增：

```cpp
class QX_DOCK_EXPORT DockStyleColors
{
public:
    QColor surface, surfaceRaised, divider, text, mutedText;
    QColor accent, accentText, onAccent, onAccentHover, onAccentPressed;
    QColor subtle, hover, pressed, tabActiveTop, tabActiveBottom;

    /*! The colours the old palette()-based sheets resolved to. */
    static DockStyleColors fromPalette(const QPalette &palette);
};

QX_DOCK_EXPORT QString dockStyleSheet(const DockStyleColors &colors,
                                      bool focusHighlighting);
QX_DOCK_EXPORT QString dockStyleSheet(bool focusHighlighting); // 不变
```

规则：

1. **旧函数转调新函数**：`dockStyleSheet(bool)` = `dockStyleSheet(DockStyleColors::fromPalette(qApp->palette()), bool)`。
   旧调用方的行为与今天一致（仍是 palette 近似），但**只有一条渲染路径**。
2. **字段可空**：`DockStyleColors` 默认构造出全是无效 `QColor`；渲染时无效字段回退到
   `fromPalette(qApp->palette())` 的同名项。漏填一个不会产出 `color: ;` 这种空声明。
3. **`fromPalette()` 是旧行为的唯一翻译**，也是「不接主题」时的合理默认：

   | 令牌 | 取自 | 说明 |
   | :--- | :--- | :--- |
   | `surface` / `tab-active-top` | `Window` | |
   | `surface-raised` / `hover` / `tab-active-bottom` | `Light` | 旧表本来就同一个角色 |
   | `pressed` | `Mid` | |
   | `divider` | `window` 亮取 `Dark`、暗取 `Light` | 分隔线要离开表面，方向由明暗决定；旧表两处方向相反，**有意改变** |
   | `text` | `WindowText` | |
   | `muted-text` | `PlaceholderText` | Qt 5.12+ |
   | `accent` / `accent-text` | `Highlight` | |
   | `on-accent` | `HighlightedText` | **C++ 侧取得到**；QSS 的 `palette(highlightedtext)` 取不到 —— 这正是 `#ffffff` 当初只能写字面量的原因 |
   | `on-accent-hover` / `-pressed` | `HighlightedText` + alpha 60 / 92 | |
   | `subtle` | `window` 亮则 `rgba(0,0,0,48)`，暗则 `rgba(255,255,255,48)` | **按亮度反转**，修掉「暗色底纹消失」 |
4. **qrc 条目从 4 条改为 3 条**（`base` / `focus` / `x11`）。这是库内部资源，不是 API；
   `CHANGELOG` 明确记「qrc 条目变化」，应用若自己复制过 qrc 需同步。
5. 版本：新增公共类型 ⇒ `qxdock` 落号时进 **0.4.0**（K11：库独立演进号）；在研期间条目写在
   `CHANGELOG` 顶端的 `Unreleased` 分节，改名只发生在落号那一笔。
6. **令牌的来源**：`fromPalette()` 只能给出「亮/暗」两套，`QxThemeManager` 装的调色板就是
   `paletteFor(dark)`——它不认识家族。而 `PALETTES` 里五个家族的 `accent` 各不相同
   （`#0072c6` … `#00a0e6`），靠调色板拿不到。要让 dock 真正跟家族走，主题必须**随身带一张
   令牌表**：
   - `tools/themes/build_themes.py` 在写 `<family>_<scheme>.css` 的同时，把同一个 `PALETTES`
     条目写成 `<family>_<scheme>.json`（键就是角色名），`res/themes.qrc` 加 10 条；
   - `QxThemeInfo` 新增 `QMap<QString, QColor> colors`（加法，不动既有字段）；
   - `qxapp::registerBundledThemes()` 读同一个 id 的 json 填进去；
   - `qxapp` 新增 `DockStyleColors dockStyleColors(const QxThemeInfo &)`，把主题角色映射成
     dock 令牌：

     | dock 令牌 | 主题角色 |
     | :--- | :--- |
     | `surface`（容器底） | `surface-sub` |
     | `surface-raised`（内容面 / 浮动标题栏） | `surface` |
     | `divider` | `border` |
     | `text` / `muted-text` | `text` / `text-muted` |
     | `accent` / `accent-text` | `accent` / `accent-text` |
     | `on-accent` / `-hover` / `-pressed` | `text-on-fill`，后两者加 alpha 60 / 92 |
     | `subtle` | `state-hover` |
     | `hover` / `pressed` | `state-hover` / `state-pressed` |
     | `tab-active-top` / `-bottom` | `surface-sub` / `surface` |

     两张表之间只有这一处对应关系，写进该函数的头文件注释；主题新增角色时只改这一处。

   ⚠️ 这一步跨三个目标（`tools` + `qxtheme` + `qxapp`），但它全是加法，且不做它，
   「dock 跟随家族」就是空话——`fromPalette()` 只能跟随明暗。验收要求 10 套主题下
   dock 的强调面取到各自家族的 `accent`（见 §六 第 7 条）。

**不改**：`applyDockIcons(const QPalette &)` / `refreshDockIcons()` 的签名。新增第三个入口：

```cpp
/*! Same as above, but the glyph on an accent fill is \c onAccent rather than
    WindowText - the colour the dock sheet uses for that surface. */
QX_DOCK_EXPORT void applyDockIcons(const DockStyleColors &colors, QWidget *root = nullptr);
```

它同时是「选中 tab 图标变黑」的收尾：按钮创建时 `isInAutoHideArea()` / `isAutoHide()`
还没置位，`refreshDockIcons()` 追不上；令牌化以后「强调面上的字形」第一次有了名字，
`setButtonIcon()` 可以在创建后由 `DockTab` / `DockAutoHideContainer` 各自再点一次
（何时点、点在哪个事件里，属于第二步的验收项，见 §六）。

## 六、验收（可执行）

1. **占位符门禁**：渲染结果里 `{{` 出现次数为 0；新增 `tests/qxdock/auto/tst_dockstyle.cpp`，
   对 `focusHighlighting` 开/关各断言一次，`x11` 片段单独渲染断言一次（X11 编译分支在
   Windows 腿跑不到，测试直接对该片段文本渲染）。
2. **等价性**：`DockStyleColors::fromPalette(亮色调色板)` 渲染出的表，与旧 4 份表
   规范化后（去掉注释、拆规则、排序）**规则集合等价**；有意不同的仅 §四表格里登记的三处，
   在测试里逐条写明原因。
3. **非空声明**：渲染结果不含 `: ;` / `:;`（Qt 会整条丢弃）。
4. **对比度**：`on-accent` on `accent`、`text` on `surface`、`muted-text` on `surface`
   各 ≥ 4.5:1，五族 × 明暗 10 套跑一遍（脚本 `scripts/check-dockstyle.py`，与
   `build_themes.py` 的闸门同思路）。
5. **视觉**：`dockdemo --theme <id>` 10 套 × autohide 展开截图；重点看
   ① 选中标签字形；② autohide 标题栏文字与按钮；③ 暗色分隔线；④ 侧边条底纹。
6. **双腿**：qt5 / qt6 各 100% 构建 + ctest（`QT_QPA_PLATFORM=offscreen`）。
7. **家族传导**：10 套主题下，`dockStyleColors(info).accent` 必须等于该主题 json 里的
   `accent`；`tst_QxTheme` 或 `tst_dockstyle` 断言 `PALETTES` 的 10 条与 theme 注册表逐条相等
   （防生成器与 bundle 漂移）。

## 七、前置项 P0：两张表的交界规则

令牌化之后 dock 表里全是**具体色值**，与主题表的具体色值同权重竞争，Qt 的规则是
**等特异性先声明者赢**。所以必须同时定下两条：

1. **拼接顺序**：主题在前、dock 在后（`demos/qxapp/dockdemo` 的 `MainWindow` 里
   `engine->styleSheet(...) + m_dockSheet` 那一处已如此）。
   写进 `dockStyleSheet()` 的文档与 `doc/pages/limitations.md` 那节。
2. **主题骨架不得声明全局 `QWidget` 背景**：`tools/themes/skeleton_dark.css` 顶部的
   `QWidget { color: {{text}}; background: {{surface}} }` 是在宣称对所有 QWidget 的所有权，
   它与 `QxDock--DockTab { background: {{surface}} }` 同权重，胜负只取决于拼接顺序。
   暗色下 autohide 面板被涂灰、tab 中间出现深色板，都是这一条造成的。
   `buildPalette` 已经把同样的颜色装进 `Window` / `WindowText`，这条规则**冗余**。
   ⇒ 删除，并在骨架里留一行注释说明「palette 已携带」。

这一项不属于 dockstyle，但**不先做，路线 A 的验收 5 一定过不了**。

## 八、不做的事（明确划出去）

- **不把 dock 表复制进 10 张主题表**：一张 366 行的表 × 10 份，改一处要改 10 处；且 qxdock
  是库、主题是应用资产，依赖方向会反。放进去的是**值**，不是行文。
- **不做 `QProxyStyle`**：那要补 `PE_/CE_` 映射，工作量数倍且应用再也改不了外观。
- **第二阶段（不在本次）**：`tabActiveShape`——选中态形态（抬高 / 下划线 / 实填）应由
  `chrome_<family>.css` 给一段声明片段，dock 表留 `{{tab-active-decl}}`。它是 `§三` 之外
  唯一还留在 dock 表里的「家族决策」，需先定片段的下发方式与门禁，单独一笔。

## 九、提交拆分（每笔原子、可独立验证）

1. `refactor(qxdock): split the dock sheets into one base and two switches`
   —— 4 → 3，逐条归一并补等价性测试；除 §四 登记的两处有意改变外行为不变。
2. `feat(qxdock): render the dock sheets from a colour set`
   —— `DockStyleColors` + overload + `fromPalette` + 旧函数转调 + `tst_dockstyle`。
3. `feat(qxdock): tint the dock glyphs from the same colour set`
   —— `applyDockIcons(const DockStyleColors &)` + 创建点补一次，修掉强调面上的字形。
4. `feat(themes): ship each theme's colour roles beside its sheet`
   —— 生成器写 `<family>_<scheme>.json`、`res/themes.qrc` 加 10 条、`QxThemeInfo::colors`、
   `registerBundledThemes()` 读 json。只加字段与文件，既有注册路径不变。
5. `feat(qxapp): map a theme's colour roles onto the dock's colour set`
   —— `dockStyleColors(const QxThemeInfo &)`，映射表就是 §五 第 6 条那一张。
6. `feat(dockdemo): drive the dock from the theme's colour roles`
   —— demo 改调新入口，`--theme` 与 `Follow system` 两条路径都走同一份映射。

每笔带 `src/libs/qxdock/CHANGELOG`（`Unreleased` 块）与 `doc/design/4.6-TASKS.md` 同笔；
第 4 笔另带 `src/libs/qxtheme/CHANGELOG`，第 5 笔另带 `src/libs/qxapp/CHANGELOG`。
