# 让 qxdock 照 qxribbon 的方式取色——路线 B 设计稿

> 状态：**设计稿，待作者确认后再开工**（2026-10-19 起草）。
> 起因：作者复核路线 A（`4.6-DOCKSTYLE.md`，已落地）后提出——「qxdock 应该像 qxribbon 那样：
> 只设置图标，图标支持明暗主题自适应，focus 时特殊处理，颜色通过 CSS 控制」。
> 本稿只回答一件事：**qxribbon 的模型在 qxdock 上为什么今天照抄会翻车，缺的那一步是什么。**
> 结论先写在前面：**作者是对的，缺的是 palette 里没有一个「本主题的强调色」角色；
> 补上它，路线 A 里那条跨库颜色链路就可以整条删掉。**

## 一、两个库今天的取色模型

| | qxribbon | qxdock（路线 A 之后） |
| :--- | :--- | :--- |
| 字形颜色 | **库自己**从 palette 按表面取：普通面 `WindowText` / `ButtonText`，强调面 `HighlightedText`（`windowbuttongroup.cpp` 的 `updateButtonIcons()`、`ribbonquickaccessbar.cpp` 的构造） | **应用喂进来**的一张令牌颜色集：主题角色表 → `qxapp::dockStyleColors()` → `DockStyleColors` |
| 其余颜色 | 主题表里 `QxRibbon--*` 规则（实色，随家族生成） | dock 表里 `{{token}}`，由同一张颜色集渲染 |
| 应用要做什么 | 装主题 | 装主题 + 取角色 + 渲染 + 染字形 + 跟两个变化源 |

对照下来，路线 A 让 qxdock 多背了一样 qxribbon 没有的东西：**「应用必须知道 dock 要哪些颜色」**。
图标只有两种表面这件事，被展开成了十五个令牌、十份 JSON、一个跨库映射函数。

## 二、qxribbon 的模型为什么成立（隐含前提）

它依赖一条没有写下来的前提：**「强调面上的字」在 palette 里有，而且与 CSS 里那块强调底色是一对。**

- 强调面的底（`close-hover` 红）写在主题 CSS 里，红底上 `HighlightedText` 几乎总可读——
  两者是**松散耦合**，红/白这个具体搭配救了它；
- `HighlightedText` 是 `qxthemepalette.cpp` 里两套 scheme 的常量，与家族无关，
  因为 qxribbon 的强调面从来不是家族强调色。

## 三、qxdock 照抄会翻车的地方（精确归因）

qxdock 的强调面**是**家族强调色：焦点标签的底、autohide 标题栏的底都是 `{{accent}}`，
五个家族五个值。而 palette 的 `Highlight` 是 `qxthemepalette.cpp` 里写死的常量，与家族无关。

于是两件事同时不成立：

1. **字形取 `HighlightedText` 不够。** 它是 `readableOn(palette 的 Highlight)` 算出来的，
   不是 `readableOn(家族强调色)`。家族强调色一旦偏亮，白字就压在亮底上——
   而主题自己是配套的：生成器对 `text-on-fill` 落在 `accent` 上有对比度门禁，
   palette 那一侧没有这个保证。
2. **「颜色全走 CSS」在字形这一项上根本不成立。** Qt 的 `palette()` 查找不接受
   `highlightedtext` / `brighttext`（整条声明被静默丢弃），所以字形色只能由 C++ 给。
   问题不是「CSS 能不能管颜色」，而是**C++ 该向谁问**。

4.6 已经实测到过一次这类错配：亮色下的 autohide 标题栏是黑字形压蓝底。
当时是在字形链路末端补的（构造后 `Show` 时重染），根因一直在上面这两条。

## 四、支点：主题的强调色要进 palette

缺的不是 qxdock 的颜色集，而是 **palette 里没有「这个应用的强调色」这个角色**。
补上之后两个库就同构了：

- `QxThemeInfo` 带一个 `accent`（无效 = 这个主题不带，退化为今天的行为）；
- `QxThemeManager::apply()` 把它写进 `QPalette::Highlight`，`HighlightedText` 用
  `readableOn()` 配好——**这段逻辑已经存在**，只是今天只在用户 override 时执行
  （`m_accentOverride`），主题的强调色走不到 palette；
- `accentColor()` 的优先级链加一层：override > 系统 accent > **主题 accent** > palette 的 highlight。

这一步做完，qxdock 就可以完全照 qxribbon 写：

| 表面 | 字形取 | 自适应 |
| :--- | :--- | :--- |
| 普通面（标签、面板、侧栏的按钮） | `WindowText`（禁用取 disabled 组） | 跟着主题明暗走 |
| 强调面（焦点标签的关闭按钮、autohide 标题栏） | `HighlightedText` | 跟着 `readableOn(家族强调色)` 走 |

而 dock 表的令牌仍旧渲染——但**由 `DockStyleColors::fromPalette()` 从（已含家族强调色的）
palette 派生**，应用什么都不用喂。`{{accent}}` 自动是家族的，因为 palette 的 Highlight 现在是家族的。

## 五、改动清单（按库）

### qxtheme

1. `QxThemeInfo`：`QColor accent;` 取代 `QMap<QString, QColor> colors`（后者是路线 A 新增、
   尚未发布，可以删）。一个主题的强调色是它的一等属性，不是一张角色表。
2. `apply()`：主题 accent 生效时写 `Highlight` / `HighlightedText` / （6.6+）`Accent`，
   与 override 同一段代码；override 优先。
3. `accentColor()`：加主题那层。
4. 生成器：`res/themes/<family>_<scheme>.json` 从「整份角色表」缩成 `{"accent": "..."}`。
5. `readBundledTheme()`：读这一个字段。

### qxdock

6. 图标：删 `applyDockIcons(const DockStyleColors &, QWidget *)` 与 `s_activeColors` 的颜色集，
   改为按表面从 palette 取色（`tintedIconForWindow(palette)` / `highlightSurfaceIconImpl(palette)`）。
   保留 `applyDockIcons(const QPalette &, QWidget *)` 作为唯一入口。
7. `DockStyleColors` 与 `dockStyleSheet(const DockStyleColors &, bool)` **保留**：它是「dock 表用什么颜色」
   的唯一入口，测试和自建皮肤的应用要用；只是默认路径不再需要应用喂。
8. `dockStyleSheet(bool)` 保持从 `qApp->palette()` 派生——palette 现在含家族强调色，
   于是「dock 跟家族」这件事由 palette 完成，不需要跨库映射。

### qxapp

9. 删 `dockStyleColors()`。
10. `applicationStyleSheet(const QxThemeInfo &)` 不再需要 theme 参数：主题表来自引擎，
    dock 表来自 palette。改为 `applicationStyleSheet()`（该重载是路线 A 新增、未发布，可改签名）。
11. `ThemeInstaller` 接口不变，内部改为「装 sheet + 用 palette 染字形」。

### 回退（路线 A 里要删的）

- 十份 JSON 的整表内容（缩成一个键）；
- `QxThemeInfo::colors`、`readBundledTheme()` 的整表分支；
- `qxapp::dockStyleColors()`；
- `tst_qxapp` 的 `bundledThemesCarryTheirRoles` / `rolesReachTheDock`
  （改为「主题带 accent」+「accent 落到 palette 的 Highlight」）。

## 六、验收

1. 十个主题逐个：`apply()` 之后 `QGuiApplication::palette().color(QPalette::Highlight)`
   等于该主题 JSON 里的 accent。
2. `QxThemeManager::accentColor()` 在无 override、无系统 accent 时返回主题的 accent。
3. dock 字形：普通面取 `WindowText`、强调面取 `HighlightedText`——用像素断言收口
   （沿路线 A 已有的 `glyphsFollowTheSurfaceOnShow` 那种写法）。
4. `dockStyleSheet(true)` 里 `{{accent}}` 渲染出的色值等于主题 accent（暗色家族取暗色那份）。
5. 无主题的应用（不注册任何主题）行为不变：palette 是 Qt 的，dock 用它的 Highlight。
6. 截图复核：家族强调色不同的两三个主题 × 明暗，autohide 标题栏字形与底对比可读。

## 七、风险与待裁定

- **影响面**：所有读 `QPalette::Highlight` 的 Qt 控件（菜单选中项、列表选中、文字选区、进度条）
  会跟着家族强调色走。判定是**期望的**——主题的强调色就是应用的高亮色，
  且 `res/themes/*.css` 里没有一处 `palette()`，主题表自身不受影响。但这一步是行为变更，需作者点头。
- `qxthememanager.cpp` 里那条注释「A theme carries a highlight colour of its own and was
  designed around it, so letting the platform's accent through by default would repaint every one
  of them」说的是**平台** accent 不该默认透传；本稿加的是**主题自己的** accent，与它不冲突，
  但注释要改写清楚，否则下一个人会读反。
- 路线 A 已落地的东西里，**dock 表的令牌化、四表归一、focus 片段、autohide 的 Show 重染全部保留**，
  回退的只有「主题带角色表 → 应用映射」这一段。
