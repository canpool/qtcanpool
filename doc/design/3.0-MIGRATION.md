# qtcanpool 2.x → 3.0 迁移指南

> 关联文档：[`../ROADMAP-3.0.md`](../ROADMAP-3.0.md) · 决策基线 K1–K6
> 结论：3.0 **不保证二进制兼容**，提供源码级迁移路径。本文档随 3.0 开发同步维护。
> **3.1 补充**：3.1 继续在同一方向上做完了 legacy 的收口（A 组），本文档相应章节已按落地结果更新——
> 受影响的主要是第 2 节（legacy ribbon 已删除）与第 3 节（`fancy*` 存废已定案）。

---

## 0. 迁移总览

| 维度 | 2.x | 3.0 | 迁移动作 |
| :--- | :--- | :--- | :--- |
| 命名空间（ribbon） | `QCanpool` | `QxRibbon` | 换命名空间 |
| 命名空间（window） | `QCanpool`（FancyWindow）/ `QxWindow` | `QxWindow` | 统一切到 `QxWindow` |
| 命名空间（app） | `QxWidget` | `QxApp` | 换命名空间（保留兼容期） |
| 头文件（ribbon） | `qcanpool/ribbonbar.h` | `qxribbon/ribbonbar.h` | 换 include |
| 构建 | qmake 为主 | CMake 为主 | 迁移到 `find_package` |
| C++ 标准 | 14（qmake）/ 17（cmake） | 17 | 统一 |
| Qt | 5.12 ~ 6.8 | 5.15（尽力）/ 6.5、6.8 | 升级 Qt |
| Ribbon 实现 | `qcanpool` 内 legacy | `qxribbon` 唯一 | 见第 2 节 |

### 0.1 3.1 带来的三处变化（必读）

3.1 的 A 组是**连续三个破坏性变更**，影响面依次递减但性质各不相同：

| 变更 | 影响 | 你会看到什么 | 怎么改 |
| :--- | :--- | :--- | :--- |
| **A3** legacy ribbon 物理移除 | `qcanpool/ribbon*.h` 不存在了 | **编译失败**：找不到头文件 | 见第 2 节 |
| **A1** 7 个通用控件迁入 `qxapp` 并改名 | 旧名仍在，但类型变了 | **弃用告警**（`is deprecated: use QxApp::Qx… instead`）+ 极少数类型不匹配错误 | 见第 3 节 |
| **A2** 11 个遗留类物理删除 | `quickaccessbar.h`、`fancytitlebar.h` 等不存在了 | **编译失败**：找不到头文件 | 见第 3 节 |

> **A1 与 A2 的区别是关键**：A1 之后旧代码**还能编**（只是告警），你有整整一个版本的时间改；
> A2 之后**不能编**，只能一次改完。升级前请先确认自己用的是哪一批名字。
>
> 另一个容易踩的点：`TinyTabBar` 现在是**独立的另一个类型**（子类），不再是 `QxTabBar` 的别名。
> 凡是把旧类型互相传递、或接收 `TinyTabWidget::tabBar()` 返回值的代码需要改（多数情况下 `auto*` 即可）。

从 `qcanpool` 到 `qxapp` 的 7 组名字对照：

| 3.0 的旧名（`QCanpool::`） | 3.1 的新名（`QxApp::`） | 旧头（保留至 3.2） | 新头 |
| :--- | :--- | :--- | :--- |
| `FancyToolButton` | `QxToolButton` | `qcanpool/fancytoolbutton.h` | `qxapp/qxtoolbutton.h` |
| `ExtensionButton` | `QxExtensionButton` | `qcanpool/extensionbutton.h` | `qxapp/qxextensionbutton.h` |
| `MenuButton` | `QxMenuButton` | `qcanpool/menubutton.h` | `qxapp/qxmenubutton.h` |
| `MenuAccessButton` | `QxMenuAccessButton` | `qcanpool/menuaccessbutton.h` | `qxapp/qxmenuaccessbutton.h` |
| `TinyTabBar` | `QxTabBar` | `qcanpool/tinytabbar.h` | `qxapp/qxtabbar.h` |
| `TinyTabWidget` | `QxTabWidget` | `qcanpool/tinytabwidget.h` | `qxapp/qxtabwidget.h` |
| `TinyNavBar` | `QxNavBar` | `qcanpool/tinynavbar.h` | `qxapp/qxnavbar.h` |

> 这些类**行为未变**，只是换名换家；改动通常就是替换标识符与 include，构造参数一一对应。

## 1. 命名空间与头文件迁移

### 1.1 命名空间

| 库 | 2.x 命名空间 | 3.0 命名空间 | 启用宏 |
| :--- | :--- | :--- | :--- |
| qcanpool（冻结） | `QCanpool` | `QCanpool`（不变） | `QCANPOOL_BEGIN_NAMESPACE` |
| qxribbon | `QxRibbon` | `QxRibbon` | `QX_RIBBON_BEGIN_NAMESPACE` |
| qxwindow | `QxWindow` | `QxWindow` | `QX_WINDOW_BEGIN_NAMESPACE` |
| qxdock | `QxDock` | `QxDock` | `QX_DOCK_BEGIN_NAMESPACE` |
| qxwidget → **qxapp** | `QxWidget` | **`QxApp`** | `QX_APP_BEGIN_NAMESPACE` |

> 升级写法（推荐显式限定，避免污染全局）：
> ```cpp
> // 2.x
> using namespace QCanpool;
> // 3.0
> QX_RIBBON_USE_NAMESPACE   // -> using namespace QxRibbon;
> ```
> 注意：三个 `*_USE_NAMESPACE` 同时展开且类名相同（如 `RibbonBar`）会**产生歧义**，迁移期建议显式写 `QxRibbon::RibbonBar`。

### 1.2 导出宏

| 2.x | 3.0 |
| :--- | :--- |
| `QCANPOOL_SHARED_EXPORT` | `QX_RIBBON_EXPORT` / `QX_WINDOW_EXPORT` / `QX_APP_EXPORT` |

### 1.3 include 路径

```cpp
// 2.x（legacy ribbon）
#include "qcanpool/ribbonbar.h"
#include "qcanpool/ribbonpage.h"
#include "qcanpool/ribbongroup.h"
#include "qcanpool/ribbonwindow.h"

// 3.0（qxapp 应用框架，推荐入口）
#include "qxapp/ribbonappwindow.h"
// 3.0（直接使用 qxribbon）
#include "qxribbon/ribbonmainwindow.h"
#include "qxribbon/ribbonbar.h"    // 内含 ribbonpage.h
#include "qxribbon/ribbongroup.h"  // 内含 ribbonbutton.h
```

## 2. Ribbon 迁移：`qcanpool` legacy → `qxribbon`

> ⚠️ **3.1 起 legacy ribbon 已物理移除**（决策 K7）。`qcanpool` 中的 `RibbonBar` / `RibbonPage` / `RibbonGroup` / `RibbonWindow` / `RibbonContainer*` 及 `QCANPOOL_CONFIG_RIBBON` 构建选项**已删除**，`fancyribbon` demo 一并移除。仍在用 legacy ribbon 的工程**必须先完成本节迁移**才能升级到 3.1+。
>
> 迁移前的过渡状态（3.0）是"保留但标 `QCANPOOL_DEPRECATED_X("use QxRibbon instead")`"——若你的代码在 3.0 上编译时已出现该告警，那些位置就是本次迁移点。

### 2.1 类对照

| legacy（`QCanpool`） | qxribbon（`QxRibbon`） | 说明 |
| :--- | :--- | :--- |
| `RibbonBar : QWidget` | **`RibbonBar : QMenuBar`** | 基类变化：qxribbon 的 RibbonBar 直接替换 QMenuBar |
| `RibbonWindow : QMainWindow` | **`RibbonMainWindow : QMainWindow`** 或 `RibbonWindow : RibbonMainWindow` | 3.0 推荐以 `RibbonMainWindow` 作基类（原生标题栏），需要无边框时用 `RibbonWindow` |
| `RibbonPage` | `RibbonPage` | 同名，接口更丰富 |
| `RibbonGroup` | `RibbonGroup` | 同名，布局模型不同（见 2.3） |
| `RibbonContainer` / `RibbonGridContainer` / `RibbonActionContainer` / `RibbonLoftContainer` | `RibbonGridContainer` / `RibbonCtrlContainer` | **语义不同，需重写**：legacy 是"容器套容器"，qxribbon 统一走 `RibbonGroup::addWidget/addGallery/addSeparator` |
| `QuickAccessBar` | `RibbonQuickAccessBar` | 由 `RibbonBar::quickAccessBar()` 获取 |
| `FancyTitleBar` | 无直接等价 | 标题栏由 `RibbonWindow` / `RibbonMainWindow` / `WindowButtonGroup` 内部处理 |

### 2.2 `RibbonBar` 方法对照

| legacy `RibbonBar` | qxribbon `RibbonBar` | 备注 |
| :--- | :--- | :--- |
| `explicit RibbonBar(QWidget *parent)` | `RibbonBar(QWidget *parent)` | 一致 |
| `addPage(const QString &text)` | `addPage(const QString &title)` | 一致 |
| `addPage(const QIcon&, const QString&)` | —（无重载） | 用 `setPageIcon`/自定义代替 |
| `insertPage(int, ...)` / `removePage` / `clearPages` | 同 | 一致 |
| `page(int)` / `pageCount()` / `pages()` | `page(int)` / `pages(bool getAll=true)` / `pageByName()` / `pageByObjectName()` | 能力更强（**`pageCount()` 用 `pages().size()` 代替**） |
| `currentPageIndex()` | `currentIndex()` | 改名 |
| `setRibbonStyle(RibbonStyle)` | `setRibbonStyle(RibbonStyle)` | **枚举值变化**，见下表 |
| `quickAccessBar()` | `quickAccessBar()` → `RibbonQuickAccessBar*` | 返回类型变化 |
| `toolBar(ToolBarPosition)` | — | 移除；用 `RibbonGroup::addWidget` |
| `titleBar()` → `FancyTitleBar*` | — | 移除；由 Window 内部管理 |
| `addAction(QAction*)` | `RibbonGroup::addLargeAction/SmallAction` | 下沉到 Group |

**`RibbonStyle` 枚举映射：**

| legacy | qxribbon | 说明 |
| :--- | :--- | :--- |
| `ClassicStyle` | `OfficeStyle` | 三行 office 风格 |
| `MergedStyle` | `WpsLiteStyle` | 两行紧凑 |
| — | `OfficeStyleTwoRow` | 新增：office 两个 tab 行 |
| — | `WpsLiteStyleTwoRow` | 新增：wps 两个 tab 行，最省高度 |

```cpp
// 2.x
#include "qcanpool/ribbonwindow.h"
using namespace QCanpool;
RibbonWindow *w = new RibbonWindow;
w->ribbonBar()->setRibbonStyle(RibbonBar::ClassicStyle);

// 3.0
#include "qxribbon/ribbonmainwindow.h"
using namespace QxRibbon;
RibbonMainWindow *w = new RibbonMainWindow;
w->ribbonBar()->setRibbonStyle(RibbonBar::OfficeStyle);
```

### 2.3 `RibbonGroup` 方法对照（重点）

**尺寸枚举**：`GroupSize{GroupLarge,GroupMedium,GroupSmall}` → `RowProportion{Auto,Large,Medium,Small}`

| legacy | qxribbon | 备注 |
| :--- | :--- | :--- |
| `addAction(const QIcon&, const QString&, GroupSize)` | `addAction(QAction*, RowProportion)` + `addLargeAction/addMediumAction/addSmallAction` | 需先建 `QAction` |
| `addAction(QAction*, GroupSize)` | `addAction(QAction*, RowProportion)` | 枚举改名 |
| `addToolButton(QToolButton*, GroupSize)` | `addWidget(QWidget*, RowProportion)` → 返回 `QAction*` | 返回值变化 |
| `addWidget(QWidget*)` | `addWidget(QWidget*, RowProportion)` | 需指定占比 |
| `removeWidget(QWidget*)` | `takeGroup`/手动移除 action | 接口不同 |
| `setTitle / title` | `setTitle / title`，另加 `setGroupName / groupName` | 兼容 |
| `setTitleFont(QFont)` | 通过样式/主题控制 | 移除 |
| `setOptionButtonVisible(bool)` + `setOptionButtonToolTip(QString)` | `addOptionAction(QAction*)` + `hasOptionAction()` | **改为 action 方式** |
| `Q_SIGNAL optionClicked()` | 绑定 option action 的 `triggered` | 信号移除 |
| — | `addGallery()` / `addSeparator()` / `addMenu()` / `setExpanding()` | 新增能力 |

```cpp
// 2.x
RibbonGroup *g = page->addGroup("File");
g->addAction(new QAction(iconNew, "New", this), RibbonGroup::GroupLarge);
g->addAction(new QAction(iconSave, "Save", this), RibbonGroup::GroupSmall);
g->setOptionButtonVisible(true);
connect(g, &RibbonGroup::optionClicked, this, &MainWindow::onOption);

// 3.0
RibbonGroup *g = page->addGroup("File");
g->addLargeAction(actionNew);          // action 复用同一 QAction
g->addSmallAction(actionSave);
g->addOptionAction(actionOption);      // option 用 action 表达
connect(actionOption, &QAction::triggered, this, &MainWindow::onOption);
```

### 2.4 `RibbonPage` 方法对照

| legacy | qxribbon | 备注 |
| :--- | :--- | :--- |
| `addGroup(const QString&)` / `addGroup(RibbonGroup*)` | 同 | 一致 |
| `insertGroup/removeGroup/clearGroups` | 同（`removeGroup` 返回 `bool`） | 一致 |
| `title() / setTitle()` | `title() / setTitle()`，另加 `pageName()/setPageName()` | `pageName` == `windowTitle`（即标签文字） |
| — | `group(int) / groupByName() / groupCount() / groupList()` | 新增 |
| — | `setCanCustomize(bool)` | 新增：支持自定义对话框 |

### 2.5 窗口与主题迁移

| legacy `RibbonWindow` | qxribbon | 备注 |
| :--- | :--- | :--- |
| `ribbonBar()` | `ribbonBar()` | 一致 |
| `setFrameless(bool)` | `setFrameless(bool)`（`RibbonWindow`）/ `updateWindowFlags()` | 一致 |
| — | `setRibbonTheme(int)` / `ribbonTheme()` / `loadTheme(file)` | 新增主题系统 |

**`RibbonTheme::ThemeStyle` 可用值**：`LightYellowTheme`、`LightOffice2013Theme`、`LightClassicTheme`、`LightFancyTheme`、`DarkWpsTheme`、`DarkOfficePlusTheme`、`CustomTheme`。

```cpp
// 3.0 主题切换
RibbonWindow *w = new RibbonWindow;
w->setFrameless(true);
w->setRibbonTheme(RibbonTheme::DarkOfficePlusTheme);
// 自定义主题
RibbonTheme::loadTheme(":/qss/custom.qss", w);
```

## 3. `qcanpool` legacy `fancy*` 控件存废（对应 K5）

> **本节已按 3.1 的落地结果更新**（原表是 3.0 时的"评估意向"，与最终处置有几处不同，
> 差异在下面第三列明确标出）。

评估时列的是意向，实际处置如下：

| 控件 | 3.0 时的意向 | **3.1 实际处置** | 替代 |
| :--- | :--- | :--- | :--- |
| `FancyToolButton` | 迁入 | ✅ **迁入** `qxapp`，改名 `QxApp::QxToolButton` | `qcanpool/fancytoolbutton.h` 保留转发一个版本（带告警），3.2 删除 |
| `ExtensionButton` / `MenuButton` / `MenuAccessButton` | 迁入 | ✅ **迁入** `qxapp`，改名 `QxExtensionButton` / `QxMenuButton` / `QxMenuAccessButton` | 同上，3.2 删除 |
| `TinyTabBar` / `TinyTabWidget` / `TinyNavBar` | 保留（迁入） | ✅ **迁入** `qxapp`，改名 `QxTabBar` / `QxTabWidget` / `QxNavBar` | 同上，3.2 删除 |
| `FancyWindow` | 迁入 | ❌ **下线**（改了意向） | `QxWindow::` 或 `QxApp::RibbonAppWindow` / `QxAppShell` |
| `FancyDialog` | 迁入 | ❌ **下线**（改了意向） | 直接用 `QDialog` / `QxApp::` 对话框能力 |
| `FancyTitleBar`、`WindowLogo`、`WindowToolBar` | 观察后下线 | ❌ **下线** | `QxWindow::` 的无边框窗口方案 |
| `MiniTabBar` / `MiniTabWidget` | 下线候选 | ❌ **下线** | `QxApp::QxTabBar` / `QxTabWidget` |
| `FancyBar` / `FancyTabBar` / `FancyTabWidget` | 评估（保留其一） | ❌ **全部下线** | 同上 |
| `QuickAccessBar` | 下线 | ❌ **下线** | `QxRibbon::RibbonQuickAccessBar` |

**两处与意向不同的地方，理由值得说清**：

- `FancyWindow` / `FancyDialog` 原计划迁入 `qxapp`。落地时发现它们不是独立窗口，而是 `FancyWindow`
  chrome 家族的**根节点**——`FancyTitleBar`、`WindowLogo`、`WindowToolBar`、`MiniTabBar` 都由它装配。
  只搬根节点、把装配方留在原处，等于在 `qxapp` 里复制一套半截的窗口框架；而 `qxwindow` 已经提供了
  完整且更现代的实现。故随 A2 一并下线。
- `FancyBar` / `FancyTabBar` / `FancyTabWidget` 原计划"三选一保留"。三者其实是同一个想法的三个名字，
  而 `Tiny*` 系列已经覆盖了它们的能力，所以全部下线。

> **迁移策略的变化**：3.0 的策略是"先加 deprecated，再移除"。3.1 之后这条已经走完——
> 保留的 7 个类**已经**是"带告警的转发头"，下线的 11 个类**已经**不存在。
> 换句话说：**3.1 之后用旧名编译，要么得到一条指向新名字的告警（前者），要么得到"没有这个文件"（后者）。**
> 后者无法靠改编译选项绕过，只能改代码——这正是本表存在的意义。

### 3.1 legacy ribbon 的 deprecated 标注（**3.1 已物理移除**）

3.0 时 `qcanpool` 的 5 个 legacy ribbon 头文件、共 **8 个类**（`RibbonBar`、`RibbonPage`、`RibbonGroup`、
`RibbonWindow`、`RibbonContainer`、`RibbonGridContainer`、`RibbonActionContainer`、`RibbonLoftContainer`）
曾被标注弃用；**3.1 中这 13 个文件已整体删除**，因此这些名字不再产生告警，而是**直接编译失败**。

请按 [§2 Ribbon 迁移](#2-ribbon-迁移qcanpool-legacy--qxribbon) 改用 `QxRibbon::`。

标注形式（**注意属性位置**：必须位于 `class` 关键字和导出宏之后、类名之前，否则会被编译器静默忽略）——此形式仍适用于 `qcanpool` 现存的 7 个转发头：

```cpp
class QCANPOOL_SHARED_EXPORT QCANPOOL_DEPRECATED_X("use QxApp::QxNavBar instead") TinyNavBar : public QX_APP_PREPEND_NAMESPACE(QxNavBar)
```

`QCANPOOL_DEPRECATED_X` 是 `qcanpool.h` 的入口宏，展开为 `QT_DEPRECATED_X(...)`；未启用弃用告警时展开为空。**在编译 `qcanpool` 库自身时它也是空的**——否则每个转发头都会对自己的声明发一条告警，把真正有用的那批淹没。

> 与 Qt 官方惯例的一处**有意的差异**：本项目的标注只控制**弃用提示**，类声明本身始终保留。因此调整 `QCANPOOL_DISABLE_DEPRECATED_BEFORE` 只会开关告警，**不会让 API 凭空消失**（Qt 原生写法会把声明一起移除）。3.2 删除这些转发头时走的是**破坏性变更**流程，不会用这个宏偷偷实现。

## 4. `qxwidget` → `qxapp` 迁移（对应 K4）

| 维度 | 2.x | 3.0 |
| :--- | :--- | :--- |
| 目录 | `src/libs/qxwidget/` | `src/libs/qxapp/` |
| 头文件 | `qxwidget_global.h` | `qxapp_global.h` |
| 命名空间 | `QxWidget` | `QxApp` |
| 宏 | `QX_WIDGET_*` | `QX_APP_*` |
| 导出宏 | `QX_WIDGET_EXPORT` | `QX_APP_EXPORT` |
| 主类 | `RibbonAppWindow` | `RibbonAppWindow`（保留） |

**兼容期方案**：**3.0 不提供转发兼容头**（M2 决策已落地 ✅）

理由：

1. K6 已明确「不保证源码兼容，提供迁移指南即可」；
2. `qxwidget` 的公开面**只有 `RibbonAppWindow` 一个类**，迁移成本 = 改 1 处 include + 改 1 处命名空间启用宏；
3. 转发头需要在 CMake / qmake 两套构建里各加一个额外 include 根，维护成本高于收益。

```cpp
// 迁移前后：改 include 路径 + 改命名空间启用宏
#include "qxwidget/ribbonappwindow.h"   // 2.x
QX_WIDGET_USE_NAMESPACE

#include "qxapp/ribbonappwindow.h"      // 3.0
QX_APP_USE_NAMESPACE
```

> 若显式限定命名空间，把 `QxWidget::RibbonAppWindow` 改为 `QxApp::RibbonAppWindow`。类名 `RibbonAppWindow` **不变**。

## 5. 构建迁移：qmake → CMake（对应 K2）

### 5.1 第三方使用（消费者）

```qmake
# 2.x（qmake 源码内联）
include($$qtcLibrarySource(qxribbon))
QTC_LIB_DEPENDS += qxribbon
```

```cmake
# 3.0（单一 CMake 包，所有库共用 QtCanpool 命名空间）
find_package(Qt6 REQUIRED COMPONENTS Core Gui Widgets)   # 或 find_package(Qt5 ...)
find_package(QtCanpool REQUIRED)

add_executable(myapp main.cpp)
target_link_libraries(myapp PRIVATE QtCanpool::qxapp)
```

> 安装时公开头文件与 `QtCanpoolConfig.cmake` 位于带 `EXCLUDE_FROM_ALL` 的 `Devel`
> 组件，需 `cmake --install <build> --component Devel`；可链接的目标为
> `QtCanpool::qxcore` / `QtCanpool::qxtheme` / `QtCanpool::qcanpool` /
> `QtCanpool::qxribbon` / `QtCanpool::qxdock` / `QtCanpool::qxwindow` /
> `QtCanpool::qxapp`。

### 5.2 库开发者

```cmake
# 3.0：add_qtc_library 已内置 install/export，无需再写 install_qtc_library
add_qtc_library(qxribbon
  VERSION ${QX_RIBBON_VERSION}
  DEFINES QX_RIBBON_LIBRARY
  DEPENDS Qt::Core Qt::Gui Qt::Widgets
  SOURCES ...)
```

### 5.3 关键变更点

- C++ 标准：`qtproject.pri` 的 `CONFIG += c++14` → `c++17`；CMake 已为 17，保持一致。
- Qt 查找：`find_package(Qt5 ...)` → 兼容写法
  ```cmake
  find_package(QT NAMES Qt6 Qt5 REQUIRED COMPONENTS Core Gui Widgets)
  find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Core Gui Widgets)
  ```
- qmake：**冻结**——`.pro`/`.pri` 不再新增特性，仅随 CMake 同步编译可用。

## 7. 常见问题（FAQ）

**Q1：能不能不迁移，继续用 2.x 的 legacy ribbon？**
3.0 可以（仍保留但已标 deprecated，不再新增功能，且不与 qxribbon 保证行为一致）。
**3.1 起不行**——legacy ribbon 源码已物理移除，`QCANPOOL_CONFIG_RIBBON` 选项也没了，
只能迁到 `QxRibbon`，或把项目留在 3.0 及以前的版本线上。

**Q2：`RibbonBar` 基类从 `QWidget` 变成 `QMenuBar`，会影响 `setMenuWidget` 吗？**
会。`RibbonMainWindow` 已内部处理 RibbonBar 与菜单区的挂载，不要再手动 `setMenuWidget`。

**Q3：还有 `RibbonPage::title()` 吗？**
有，等价于 `pageName()`；标签文字实际取 `windowTitle`，用 `setPageName()` 或 `setTitle()` 均可。

**Q4：命名空间 `using namespace` 冲突怎么办？**
不要同时展开 `QxRibbon` 与 legacy `QCanpool`；跨库引用请显式限定（`QxRibbon::RibbonBar`）。

**Q5：升级到 3.1 时旧名编译失败，最快的定位办法是什么？**
先按失败的头文件分类：`qcanpool/ribbon*.h` → 见第 2 节（A3）；
`qcanpool/{quickaccessbar,fancytitlebar,windowlogo,windowtoolbar,minitab*,fancybar,fancytab*,fancywindow,fancydialog}.h`
→ 见第 3 节（A2，**无同名替代**）；`qcanpool/{fancytoolbutton,extensionbutton,menubutton,menuaccessbutton,tiny*}.h`
→ 这些还能编（只有告警），按 §0.1 换成 `qxapp/qx*.h`（A1）。
