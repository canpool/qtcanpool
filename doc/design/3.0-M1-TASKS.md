## T1.1 统一 C++ 标准为 C++17

**背景**：`qtproject.pri` 用 `CONFIG += c++14`，CMake 用 `CMAKE_CXX_STANDARD 17`，存在分裂。

**步骤**：
1. 编辑 `qtproject.pri`：`CONFIG += c++14` → `CONFIG += c++17`。
2. 确认 `CMakeLists.txt` 已设 `set(CMAKE_CXX_STANDARD 17)` + `STANDARD_REQUIRED ON`（已是，无需改）。
3. 全局检索 C++14 特有写法与 C++17 冲突点（如 `std::auto_ptr`、`register`）。

**涉及文件**：`qtproject.pri`、`CMakeLists.txt`

**验收**：qmake 与 CMake 构建均以 C++17 通过；`grep -rn "c++14" .` 无结果（`build/` 除外）。

## T1.2 Qt 版本策略（K1）

**实测更正**：原以为 `find_package(Qt5 ...)` 是"硬编码 Qt5"，实际仓库的 `cmake/FindQt5.cmake` 是一个 **Qt6 优先的包装层**——它先 `find_package(Qt6 ...)`，找不到才回退 Qt5，并把 `Qt5::X` 别名为 `Qt6::X`，同时 `set(Qt5_VERSION ${Qt6_VERSION})`。因此：
- 顶层 `find_package(Qt5 ...)` **无需改写**，已自动优先 Qt6；
- `if (Qt5_VERSION VERSION_LESS 6.0.0)` 这类判断也是正确的（取到的是 Qt6 版本）；
- 各库 `DEPENDS Qt5::Core` 同样可用（别名机制）。

**因此本任务的真实动作**：把最低版本从 5.14.0 提升到 **5.15.0**，落实 K1（放弃 ≤5.14）。

```cmake
# cmake/QtCanpoolAPI.cmake
set(IDE_QT_VERSION_MIN "5.15.0")
```

**涉及文件**：`cmake/QtCanpoolAPI.cmake`（已改）

**验收**：✅ 用 Qt 6.8.3 完成 configure + generate 通过（见执行补充）。

## T1.5 跨平台 CI 矩阵（P0）

**步骤**：新增 `.github/workflows/ci.yml`（Gitee 侧可另配 `.gitee/workflows` 或 Gitee Go）。

```yaml
name: CI

on:
  push:
    branches: [ master, develop ]
  pull_request:
    branches: [ master, develop ]

jobs:
  build:
    name: ${{ matrix.os }} / Qt ${{ matrix.qt }}
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        include:
          - { os: ubuntu-latest,  qt: '6.8.1' }
          - { os: windows-latest, qt: '6.8.1' }
          - { os: macos-latest,   qt: '6.8.1' }
          - { os: ubuntu-latest,  qt: '5.15.2' }
    steps:
      - uses: actions/checkout@v4

      - name: Install Qt
        uses: jurplel/install-qt-action@v4
        with:
          version: ${{ matrix.qt }}
          cache: true

      - name: Configure
        run: cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DWITH_TESTS=ON

      - name: Build
        run: cmake --build build --config Release --parallel

      - name: Test
        run: ctest --test-dir build -C Release --output-on-failure
```

**涉及文件**：`.github/workflows/ci.yml`（新增）

**验收**：PR 触发后 4 个矩阵任务均绿灯（或明确记录已知失败并挂 TODO）。

## T1.6 clang-format 校准（P1）

**实测更正**：仓库**已存在**一份完整的 `.clang-format`（Qt 风格：4 空格缩进 / 指针右靠 / `BreakBeforeBraces: Linux` / `ColumnLimit: 120`）。因此无需新增，只需与 C++17 对齐并校验。

**已完成**：
1. `.clang-format`：`Standard: Auto` → `Standard: c++17`（与 T1.1 一致，帮助解析结构化绑定、嵌套命名空间等语法）。
2. 用本机 clang-format 21.1.8 校验：`--dump-config` 与真实文件格式化均 **exit 0、无告警**。
3. CI 已加入 `clang-format` 任务，当前为**提示模式**（`continue-on-error: true`）。

**已完成（收尾）**：
4. 全量格式化：`src/ demos/ examples/ tests/ projects/` 共 **233 个文件**改动（`+1358/-1485`），作为**单独一次提交**（`style: apply clang-format`），与功能提交隔离。
5. CI format 任务转为**强制门禁**：去掉 `continue-on-error`，并用 `pip install 'clang-format==21.1.8'` **固定版本**（避免 runner 自带版本漂移导致误报）。
6. 补充配置：`ForEachMacros` 增加 Qt 的 `foreach` / `Q_FOREACH`（原先只认大写 `FOREACH`，导致 24 处 `foreach (` 被误改成 `foreach(`）。

**实测结论**：
- `git diff -w` 复核：剩余差异全部为空白/注释换行/大括号归位等**纯格式**改动，无语义变更；
- 格式化后**全量构建 EXIT=0、`ctest` 4/4 通过**；
- BOM 与 CRLF **逐文件保留**（`DeriveLineEnding: true`），无整文件重写；
- 用 CI 同款命令（`git ls-files ... | clang-format --dry-run --Werror`）复核：**exit 0、0 违规**。

**验收**：✅ 配置可解析；✅ 全量格式化完成；✅ 门禁转正（exit 0）。

# tests/CMakeLists.txt
find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Test)

function(qtcanpool_add_test name)
  add_executable(${name} ${ARGN})
  target_link_libraries(${name} PRIVATE
    Qt${QT_VERSION_MAJOR}::Test Qt${QT_VERSION_MAJOR}::Widgets)

### 发现的问题（M1 执行中）

1. **ribbondemo CMake 失效**：`RibbonAppWindow` 已移入 `qxwidget` 库，但 demo 的 CMakeLists 仍引用本地 `ribbonappwindow.cpp`，导致 CMake **generate 阶段直接失败**（qmake 侧早已更新）。
2. **库的 Qt 依赖为 PRIVATE**：导致测试/下游包含 `qxribbon/xxx.h` 时找不到 `<QToolButton>` 等，编译失败。已改为 `PUBLIC_DEPENDS`。
3. **`qxwidget` 缺库依赖**：CMakeLists 未声明 `qxribbon` / `qxwindow`（`.pri` 中有），链接时大量 `undefined reference to QxRibbon::* / QxWindow::*`，CMake 下 `qxwidget` 从未能构建。已补齐。
4. **`cmake/FindQt5.cmake` 实为 Qt6 优先包装层**（见 T1.2 更正）。

> 备注：完整构建产生了若干 **Qt6 弃用告警**（`QMouseEvent::globalPos()`、`QHoverEvent::pos()`、`qAsConst`、`QAction::parentWidget<T>()` 等），集中在 `qcanpool` 与 `qxwindow`。非 M1 阻塞项，建议归入 M2/M3 的代码现代化清理。
