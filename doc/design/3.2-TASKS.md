### 3.1 D1 · i18n 基础设施（`qxcore`）

**目标**：让应用能装载/切换翻译，并在切换后**运行时重翻译**。

**新增**：`src/libs/qxcore/qxtranslator.h` / `.cpp`（+ `qxtranslator_p.h` 视实现需要）

**API 草案**：

```cpp
class QX_CORE_EXPORT QxTranslator : public QObject
{
    Q_OBJECT
public:
    explicit QxTranslator(QObject *parent = nullptr);
    ~QxTranslator() override;

    /* 语言包目录；Qt 自带翻译按 qtbase_<lang>.qm 一并尝试装载 */
    QString translationPath() const;
    void setTranslationPath(const QString &path);

    /* 扫描目录里存在的语言（应用前缀 + qtbase 前缀的并集） */
    QStringList availableLanguages() const;

    QString language() const;
    /* 装载并应用；失败返回 false，当前语言不变 */
    bool setLanguage(const QString &language);
    /* 诊断用：本次实际装载的文件 */
    QStringList loadedFiles() const;

Q_SIGNALS:
    /* 非 widget 消费方（模型/控制器）收不到 QEvent::LanguageChange，这是存在它的核心理由 */
    void languageChanged(const QString &language);
};
```

**要点**：

- 装/卸走 `QCoreApplication::installTranslator()` / `removeTranslator()`；切换时先卸旧的再装新的，
  Qt 会自动给所有顶层 widget 投递 `QEvent::LanguageChange`。
- **语言枚举只扫目录，不依赖 `lrelease`**；找不到 Qt 自带翻译**不算失败**，只装应用翻译。
- 持久化交给调用方（或提供 `restore(QxSettings *)` 便利），保持单一职责——`qxcore` 内两者同库，
  可直接复用 `QxSettings`。
- **测试**（`tests/qxcore/auto/tst_qxtranslator.cpp`）分两层，**不制造假绿**：
  1. 机制层（总是跑）：用 `QTemporaryDir` 放桩文件，断言枚举结果、装/卸后的状态迁移、
     `languageChanged` 信号、失败路径不改状态；
  2. 生效层（条件跑）：若测试数据里带真 `.qm`（由 `lrelease` 生成），断言 `QCoreApplication::translate()`
     前后文案真的变化；**拿不到就 `QSKIP` 并打印原因**，不用桩文件假装通过。

### 3.2 D2 · Toast 应用内通知（`qxapp`）

**目标**：应用内轻提示——带级别、自动消失、可堆叠、可挂到 `QxAppShell`。

**新增**：`src/libs/qxapp/qxtoast.h`/`.cpp`、`qxtoastmanager.h`/`.cpp`（+ `_p.h`）

**组成**：

| 类                | 职责                                                                 |
| :--------------- | :----------------------------------------------------------------- |
| `QxToast`        | 无边框 + 半透明 + 阴影的提示条 widget；带 `Level`（Information/Success/Warning/Error）、自动消失、悬停暂停、淡入淡出 |
| `QxToastManager` | 管理**同一宿主窗口**同屏多条 toast 的堆叠与淘汰；每条一个超时                                       |
| `QxAppShell`     | 新增 `showToast(text, level, timeoutMs)` 便利入口（"可挂到 AppShell"）        |

**要点**：

- **不依赖真实窗口管理器**：`Qt::ToolTip` / `FramelessWindowHint` + `WA_ShowWithoutActivating`，
  不置顶、不抢焦点——否则 headless 测试与 WASM 构建都会被拖下水。
- 级别 → 配色走 `qxtheme` 的调色板，**不硬编码颜色**（与主题联动）。
- 测试把**模型与渲染分开**：堆叠顺序、超时淘汰、级别映射放在可 headless 断言的部分
  （`QxToastManager` 的队列状态），widget 只在 offscreen 冒烟。
- 文档页：`doc/pages/components.md` 补 `QxApp` 一节。

**测试**：`tests/qxapp/auto/tst_qxtoast.cpp`（追加到现有 `tests/qxapp/auto/`）。

### 3.3 D3 · 属性编辑器内核（`qxapp`）

**目标**：一个"键值表单"内核，供 D4 复用；**这是设置对话框的地基，不是给用户直接用的控件**。

**新增**：`src/libs/qxapp/qxproperty.h`（描述符）、`qxpropertyeditor.h`/`.cpp`

**API 草案**：

```cpp
struct QX_APP_EXPORT QxProperty
{
    enum Type { Bool, Int, Double, String, Text, Enum, Color, Font, Path };
    QString     key;            /* 稳定键名，对话框据此读写 QxSettings */
    QString     label;
    Type        type = String;
    QVariant    value;
    QVariant    defaultValue;
    QStringList choices;        /* Enum 专用 */
    QString     tooltip;
    bool        readOnly = false;
};

class QX_APP_EXPORT QxPropertyEditor : public QWidget
{
    Q_OBJECT
public:
    void addProperty(const QxProperty &property);
    void addGroup(const QString &title, const QList<QxProperty> &properties);

    QVariant value(const QString &key) const;
    void setValue(const QString &key, const QVariant &value);
    void setAllValues(const QHash<QString, QVariant> &values);
    QHash<QString, QVariant> allValues() const;

    bool isModified() const;
    void reset();              /* 回到 defaultValue */
    void resetToInitial();     /* 回到 setAllValues 时的值 */

Q_SIGNALS:
    void valueChanged(const QString &key, const QVariant &value);
    void modifiedChanged(bool modified);
};
```

**要点**：

- 类型 → 控件映射：`Bool`→`QCheckBox`、`Enum`→`QComboBox`、`Int`/`Double`→`QSpinBox`/`QDoubleSpinBox`、
  `Path`→`QLineEdit` + 浏览按钮、`Color`→色块按钮、`Text`→`QTextEdit`。
- **不绑定 `QxSettings`**：内核只认 `key`/`value`，绑定是 D4 的职责——否则内核为了"能测"会被
  迫拖上一整个 settings 后端。
- 测试：类型映射、取值/设值、`isModified` 迁移、`reset` / `resetToInitial`、信号。

**测试**：`tests/qxapp/auto/tst_qxpropertyeditor.cpp`。

### 3.4 D4 · 设置对话框（`qxapp`）

**目标**：分组 + 表单 + 应用/取消语义的通用设置界面，对接 `QxSettings`。

**新增**：`src/libs/qxapp/qxsettingsdialog.h`/`.cpp`

**API 草案**：

```cpp
class QX_APP_EXPORT QxSettingsDialog : public QDialog
{
    Q_OBJECT
public:
    explicit QxSettingsDialog(QX_CORE_PREPEND_NAMESPACE(QxSettings) *settings,
                              QWidget *parent = nullptr);

    void addPage(const QString &id, const QIcon &icon, const QString &title,
                 const QList<QxProperty> &properties);
    void addGroup(const QString &pageId, const QString &title,
                  const QList<QxProperty> &properties);

    void apply();
public Q_SLOTS:
    void accept() override;   /* 应用 + 关闭 */
    void reject() override;   /* 丢弃 */
Q_SIGNALS:
    void applied();
};
```

**要点**：

- 布局：左侧分类（`QListWidget`）+ 右侧 `QxPropertyEditor`（D3）+ `QDialogButtonBox`（确定/取消/应用）。
- 打开时按 key 从 `QxSettings` 读值（`setAllValues`），`apply()` 写回并 `sync()`；
  descriptor 的 `defaultValue` 即"未设置时的值"。
- **不做迁移**：`QxSettings::migrate()` 属**应用启动期**职责，不是对话框的——文档要写清这个分界。
- 测试：用**临时文件的 `QxSettings`**，断言 `apply()` 后键值落盘、`reject()` 后原值不变、
  `reset()` 回默认值。

**测试**：`tests/qxapp/auto/tst_qxsettingsdialog.cpp`。

## 六、风险与注意

- **R1 是破坏性的，且与 3.1 的破坏性不同**：3.1 的 A1 之后旧名**仍能编译**（只有告警），
  R1 之后旧名**不存在**。迁移文档必须把这个区别写清楚（沿用 `3.0-MIGRATION.md` 里 A1/A2 的对比写法）。
- **qmake 冻结面必须连带改**：`libs.pro` / `examples.pro` / `staticlink.pro` 漏改会让冻结构建断裂。
  这属于"维持冻结构建可用"的必要维护，不是新增特性。
- **i18n 的测试不能造假绿**：没有 `lrelease` 就测不出"翻译真的生效"——此时**跳过并打印原因**。
- **Toast 不要依赖窗口管理器**：置顶/抢焦点会同时拖垮 headless 测试与 WASM 构建。
- **属性编辑器与设置对话框的边界**：内核只认 key/value；绑定 `QxSettings` 是对话框的职责。
- **不要为凑能力扩范围**（K10）：工作区预设、状态栏进度已明确留在 3.3。
