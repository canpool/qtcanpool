## 一、这一版做什么

**一句话：五个千行 `.cpp` 按职责拆开（A 组），再把滚动追加池点名的六件控件造出来（B 组），
别的一个字都不动**（新界面风格库原拟进本版，作者 2026-10-22 裁定移出、4.7.2 引入两家，
见 §二 C 组）。

两半的产物性质不同——A 组是**搬家**（源码行数不变、行为不变、公开面不变），B 组是**增量**
（全新文件，只加不改）——所以判据分两套（§四），互不污染。

### 1.1 为什么这两半能放进同一个 patch

1. **作者口径。** 2026-10-22 明确定范围：重构**放进** 4.7.1 但不**限于** 4.7.1；滚动池
   （C6 / D5）的组件**也要实现**。初稿「只做重构」已被作者否决。
2. **K36 的表两半都覆盖得到。** 「内部重构，公开面与默认行为不变 ⇒ patch +1」管 A 组；
   「新增能力（加类 / 加函数）⇒ patch +1」管 B 组。两半都到不了 minor 的三个触发器
   （改签名 / 删 API / 改默认行为——后者已被 §1.5 拿走），所以**这一版是 patch**，
   不需要为任何一半找陪衬、也不需要把哪一半推到下一个 minor。
3. **文件不重叠 ⇒ 可独立回滚。** A 组动 `qxribbon` / `qxdock` 的既有 `.cpp`，B 组只在
   `qxfluent` / `qxmaterial` 里加新文件。这是两半能放在同一版而不互相污染的原因，
   也是判据要分两套的原因：A 组的 ①（多重集相同）在 B 组面前没有意义，B 组的 ⑦（纯增量）
   在 A 组面前也没有意义。

### 1.2 为什么先拆后建（执行序的理由）

```
A 组（R1–R5）全部落地  →  B 组（Y1–Y6）逐件落地  →  S8 重基线  →  S6 文档  →  结算
```

1. **① 的多重集比对在「只有拆分在动」的树上最干净。** B 组落过之后五个文件本身没动、
   ① 照样成立，但审阅者要在「新控件 + 搬家」混在一起的 diff 里找搬家证据。
2. **④ 的金标零差必须在 gallery 变化之前对齐。** B 组必然给 gallery 加行
   （`materialpage.h` 的注释写死了「one row for every control QxMaterial ships」），
   所以 A 组的 ④ 只能跑在 B 之前；反过来说，B 组落完 gallery 必然变，重基线是**计划内**
   动作（S8），不是失败。
3. **反证的用法。** A 组期间 `dockdemo.png` 与 `controlgallery.png` 都该零差；B 组期间
   `controlgallery.png` 必然变（重基线），而 `dockdemo.png` 仍必须零差——B 组不碰 dock，
   它变了就说明 B 组碰到了不该碰的东西。

### 1.3 口径澄清：4.4 的"拆分"不是拆文件

`4.4-TASKS.md:38` 把 `ribbonbar.cpp`（当时 1961 行）列为「单文件巨石拆分」，A1-T1「已收口」。
**实际落地的是抽公共块去重**（`placeCornerWidget()` / `layoutTabBar()` / `paintPageContextTabs()`，
见 `4.4-TASKS.md` §七 `0314c153`、`39a38c3f`），**没有拆成多个 `.cpp`**。文件因此从 1961 行
涨到 2385 行（4.7.0 又往里加了 QAB 晚到样式表、样式四值、KeyTips 等）。

⇒ A 组做的不是"把 4.4 没做完的补上"，而是**换一种拆法**：不合并重复、只搬移位置。
两者判据不同（去重要改代码，搬家不许改代码），所以不要拿 4.4 的提交当模板。

⚠️ 引用口径：`4.7-TASKS.md` §二 写的是「`ribbonbar.cpp` 2353」——那是 4.7.0 **收尾前**的数；

### 1.4 硬约束（4.7.0 §1.3 六条照旧，本版另加四条）

4.7.0 §1.3 的六条（双腿 / Qt 6 独有 API / 源文件不带 BOM / 图标 / 主题族 id / 不引第三方 /

- ⚠️ **B 组只加不改**。既有源码文件（两库的 `.h` / `.cpp`）一行不碰；允许改的只有

⚠️ 第二条「只加不改」是**提交卫生**（新增笔里不夹带修复），**不是**「行为不许改」的政策禁令——

## 二、任务分解

### 2.0 A 组的三种"搬家必需"改动（除此之外一行不动）

搬移必然带来三类文本变化，**预先声明、审核时按这三类认**：

| 类别 | 内容 | 影响 |
| :--- | :--- | :--- |
| **N1 文件外壳** | 新 `.cpp` 的版权头、`#include` 清单、`QX_*_BEGIN_NAMESPACE` / `QX_*_END_NAMESPACE` 包裹 | 无（每个 TU 各一份） |
| **N2 助手换处** | 原本 `static` 在 `.cpp` 里的**常量 / 纯函数 / 宏**，若被两个以上的新文件用到，搬进该库的 `_p.h` 并改写成 `inline`（常量写 `inline constexpr int`，C++17 已开启，见根 `CMakeLists.txt:30`） | 无（仍是每个 TU 一份，链接期不冲突） |
| **N3 私有类头文件化** | qxdock 四个私有类**原本定义在 `.cpp` 里**，拆分要求两个 `.cpp` 看见同一份定义 ⇒ 原样搬进 `<class>_p.h`（**连同成员的默认值、内联函数体、声明顺序一起搬，一个字不改**） | 无 ABI 影响（私有类本就不导出，公开类经 d-pointer 的尺寸布局不变；`AUTOMOC` 不受影响，实测这五个 `.cpp` 里**没有** `Q_OBJECT`，也没有 `#include "*.moc"`）。⚠️ 但 `_p.h` **会被安装**——`set_public_headers` 把 SOURCES 里所有 `.h` 装进 Devel 组件（`cmake/QtCanpoolAPIInternal.cmake:222`，qxribbon 已有 14 个先例）⇒ 记录口径是「私有实现定义进入**已安装但不属导出 API** 的头」，architecture.md 的说明句按这个写（S6） |

⚠️ **`static` 变量不适用 N2**：带状态的 `static`（本批只有一个 `qxdock/dockcontainer.cpp:28`
的 `s_zOrderCounter`）**绝不能进头文件**——进了就是每个 TU 一份副本，z 序就不唯一了。它跟
唯一使用者 `DockContainer::event()` 走同一个文件（实测只有 `1666`/`1668` 两处引用）。

#### Y1 · `FluentNumberBox`（输入层）

- **台账原话**（C6 第 2 条）：「带校验与步进器的数值输入，QSpinBox 缺的形态」。
- **形态**：`QxControl` 子类，内嵌 `QLineEdit`（Qt 的文本编辑不自己造）。步进器是
  **右侧上下两枚 chevron**，不是旋转框——旋钮是「旧世界」的答案，Fluent 没有它。
- **校验**：非数字输入不进入 `value`；失焦把显示拉回 `value`（口径同 4.7.0
  `FluentCommandBar` 的「问的时候才算」——不缓存过期状态）。
- **接口方向**：`minimum` / `maximum` / `singleStep` / `value` + `valueChanged`。
- **键盘**：上下键一步、PageUp / PageDown 大步（档位实施时定）。
- **无障碍**：role `SpinBox` + `QAccessibleValueInterface`（`FluentSlider` 之后的第二个消费者）。
- **测试量级**：6–8 条（像素探针测步进按钮与焦点态；行为测校验与值域）。

#### Y2 + Y3 · `FluentDropDownButton` / `FluentToggleSplitButton`（命令层，两类两笔）

- **台账原话**（C6 第 3 条）：「`DropDownButton` / `ToggleSplitButton`（`CommandBar` 的两个
  组成件，先在 `CommandBar` 内部实现，值得独立导出时再拆出）」。
- **现状实测**（2026-10-22）：内部件已经在 `fluentcommandbar.cpp` 里活着——chevron 绘制
  `paintChevron()`（66–78 行，`kChevronWidth = 20` / `kChevronGlyph = 8`）、Split 的 chevron
  热区（`item.chevron`，87 / 185 行）、菜单弹出（238–242，`menu->popup(mapToGlobal(...))`）、
  点击判定（259–263）。⇒ 本项是**抽出**，不是从零画。
- **抽法**（两种，见 Q7）：(a) 抽成两个独立 `QxControl` 子类、`CommandBar` 暂不动
  （4.7.1 只加不改，改复用排 4.7.2）；(b) 抽出的同时让 `CommandBar` 内部改用这两个类
  （消重，但有行为风险，与 B 组「只加不改」的硬约束冲突）。**助手建议 (a)**。
- **形态分野**（两件都必须讲清，否则不知道为什么是两个类）：
  - `DropDownButton`：**整面即菜单**——点哪都开，没有「主点击」这回事；
  - `ToggleSplitButton`：**左半是开关**（按下去保持），**右半 chevron 开菜单**——
    「做」与「选更多」是两件事，不许合并成一次点击。
- **无障碍**：`DropDownButton` role `Button`；`ToggleSplitButton` 左半 checkable ⇒
  role `CheckBox` + checkable / checked（同 `FluentSwitch` 的处理）。
- **测试量级**：各 6–8 条。

#### Y4 · `FluentContentDialog`（反馈层）

- **台账原话**（C6 第 4 条）：「模态内容对话框，Qt `QDialog` 缺的观感与动作布局」。
- **实现选型**（见 Q8）：`QDialog` 子类 + 自绘 surface（投影走 `QxShadowPainter`，

  底部动作条（主 / 次 / 关闭，最多三个；按钮是「问不是做」，由应用去连——同

- **测试量级**：6–8 条。

#### Y5 · `MaterialTextField`（输入层）

- **台账原话**（D5 其后）：「`TextField`（浮动标签 + 填充/描边两态，`QLineEdit` 缺的形态）」。
- **两态**（M3 认它的地方）：
  - **filled**：填充容器 + 底部一根指示线；聚焦时线变粗变色、标签上浮；
  - **outlined**：描边容器，标签**嵌进描边**（在边框上「开窗」）。

  `QLineEdit` 的 placeholder 替不了这个——placeholder 在输入后消失，标签不消失。
- **结构**：`QxControl` 子类内嵌 `QLineEdit`；无障碍 role `EditableText`。
- **测试量级**：8–10 条（浮动标签两态的几何是重点，像素探针）。

#### Y6 · `MaterialDialog`（反馈层）

- **台账原话**（D5 其后）：「`Dialog`（M3 的 basic / full-screen 两档）」。

## 四、验证判据（逐条给命令）

判据分两套：**A 套**（①–⑥）只管搬家，**B 套**（⑦–⑩）只管增量。一套绿了不代表另一套。

### A 套 · 搬家判据

#### ① 纯搬移（笔级，每笔必跑）

```bash
# 基线取上一次发版的 tag（4.7.1 期间用 4.7.0；拆第二笔起用上一笔的 SHA 也行，判据相同）
git show 4.7.0:src/libs/qxribbon/ribbonbar.cpp > build/move/ribbonbar-before.cpp
python build/check_pure_move.py build/move/ribbonbar-before.cpp \
    src/libs/qxribbon/ribbonbar.cpp src/libs/qxribbon/ribbonbarlayout.cpp \
    src/libs/qxribbon/ribbonbarpaint.cpp src/libs/qxribbon/ribbonbarprivate.cpp \
    src/libs/qxribbon/ribbonbarstackedwidget.cpp src/libs/qxribbon/ribbonbar_p.h
```

脚本做的事：两侧都**丢掉**版权头注释块、`#include` 行、`#pragma once`、`QX_*_BEGIN/END_NAMESPACE`、
空行，然后把剩下的行**排序成多重集**比。期望输出：`only-before` 与 `only-after` 两栏**都为空**
（`N2` 的 `inline` / `inline constexpr` 修饰符在脚本白名单里等价归一）。

#### ② 公开面零变化（库级，一个库拆完跑一次）

```bash
git diff --stat 4.7.0..HEAD -- \
    'src/libs/qxribbon/*.h' 'src/libs/qxdock/*.h' \
    ':(exclude)src/libs/qxribbon/*_p.h' ':(exclude)src/libs/qxdock/*_p.h'
# 期望：空输出（一个字节都没有）
```

⚠️ 三个坑，都实测过：

1. **不能用 `[!_]` 之类排除 `_p.h`**——`_p.h` 是**后缀**不是前缀（`ribbonbar_p.h` 以 `r` 开头），
   要用 `:(exclude)` 或 `*_p.h` 的模式。
2. **不能写成 `'src/libs/qxdock/**/*.h'`**：`**` 会吃掉一层目录名，**紧贴库目录的头文件匹配不到**
   （`release.md` 已记这个坑）。
