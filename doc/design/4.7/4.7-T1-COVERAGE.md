## 零、怎么读这一页

### 五个记号

| 记号 | 意思 | 出处 |
| :---: | :--- | :--- |
| `●` | 有断言 | T1 的三句话之一 |
| `○` | 只测了默认态 | T1 的三句话之一 |
| `—` | 本件不适用 | T1 的三句话之一，理由写在同一行的「不适用理由」列 |
| `✗` | 不支持 | T1-c 追加的一格 |
| `∅` | 无用例 | **助手补的第五个记号，作者未拍板** |

多出 `∅` 的理由：台账那三句话是给**有用例的格子**定的。`FluentCard` 与 `FluentDivider` 没有专题用例
（前者只在 badge / reveal 的用例里当宿主，后者只在 button 的用例里当背景），把它们写成「只测了默认态」
是撒谎——默认态也没测过。所以单立一格，代价是记号从四种变五种。

### 「有断言」的判据

不看文件里有没有出现那个词，看**用例有没有自己把件推进那个状态**：`QTest::mouseClick` 打开菜单、
`QTest::key(Qt::Key_Right)` 走格子、`setEnabled(false)` 看它变灰、`QPalette` 换一套再看像素。
只读一次默认值、或注释里提到方向，都不算。

⚠️ **这一点必须写在最前面，免得 `●` 被当成保证**：`●` 只证明「有人去过」，不证明「那道门有锁」。
要证明后者得让用例红一次——先改坏实现看它红，再还原看它绿。那一步在 T1-a / T1-b 里做，
按台账规矩，**红不了的用例不进 T1**。所以本页的 `●` 是候选，不是结论。

### 四种「不适用」的理由

| 代码 | 适用件 | 理由 |
| :--- | :--- | :--- |
| 非控件 | `FluentReveal` · `FluentWindowMaterial` · `MaterialRipple` · `QxStateLayer` · `QxRingPainter` · `QxShadowPainter` | 派生自 `QObject` 或本身就是命名空间的绘制助手：不进焦点链、不产生可访问对象、无自身几何 |
| 纯装饰 | `FluentBadge` · `FluentDivider` · `MaterialBadge` · `MaterialDivider` · `MaterialSkeleton` | 不接收输入、不进入焦点链 |
| 只作指示 | `FluentProgressBar` · `FluentProgressRing` · `MaterialProgress` · `MaterialProgressRing` | 不接收指针、不进入焦点链（禁用态仍要管：变灰是看得见的行为） |
| 令牌 | `FluentShape` / `FluentType` · `MaterialShape` / `MaterialType` / `MaterialElevation` / `MaterialMotion` | 尺寸、颜色、高程等呈现常量，不含交互状态。时长档位是例外：它随「减弱动效」变，那一格照实记 |

**证据优先于理论**：一个件若被写成了装饰，但用例确实把它点亮过（`MaterialBadge` 断言过焦点策略），
格子记 `●` 而不是 `—`。件能进那个状态，就说明它有那个状态。

## 四、右到左与 DPR（T1-c）

### 右到左：不支持

| 项 | 内容 |
| :--- | :--- |
| 议题 | 两族要不要支持布局方向镜像（`Qt::RightToLeft`） |
| 决定 | **不支持** |
| 依据 | `src/libs/qxfluent` / `qxmaterial` / `qxcontrols` 三处搜 `RightToLeft` / `setLayoutDirection` / `isRightToLeft` / `LayoutDirection`：**0 命中**——没有一处读过方向。`QxControl` 之外的自绘几何按左起写死，例如 `fluentbreadcrumbbar.cpp:159` 的 `Qt::AlignLeft` |
| 处置 | 矩阵该列记 `✗`；`doc/pages/limitations.md` 加条目；**不造用例**（不假装支持） |

需要说清的分寸：走 `QLayout` 排出来的几何会跟着方向自动镜像，所以「整块面板左右对调」这类粗粒度行为
未必看得出来；坏掉的是**自绘的左右语义**——内边距起边、指示条贴哪一侧、箭头指向、进度从哪头长。
本条说的是后者没有实现，不是说前一种会崩。

### DPR：无用例，但**不**判不支持

八维里没有 DPR 这一列，T1-c 却要求一并判。实测两族用例 **0 处**碰过 `devicePixelRatio`，
像素断言全部在 `offscreen`（DPR = 1）下取样，所以 DPR ≠ 1 的显示没有任何用例走过。

但下「不支持」的判语需要证据，这里没有：两库的绘制都用逻辑像素，缩放交给 Qt 的绘制管线。
所以结论是**「没用例」**，不是「不支持」——差别在于前者是欠账（将来补一条 DPR = 2 的取样用例即可），
后者是能力缺口。这条留在 `limitations.md` 里按「未知」写，不按「已知缺陷」写。

## 五、怎么复算

```bash
python scripts/t1_coverage.py            # §二 的三张表
python scripts/t1_coverage.py --debt     # §三 的汇总与逐维清单
python scripts/t1_coverage.py --stats    # 只出记号计数，改用例后先看这个
```

脚本做两件事：按 `DRIVEN` 里的正则判「用例有没有主动把件推进那个状态」，再按 `NA` 里的四类理由
把不可能有的格子判成 `—`。**行清单**（哪件、哪个用例文件、属于哪类理由）写在脚本顶部的
`FLUENT` / `MATERIAL` / `SHARED` 三张表里——新增控件时先加行，矩阵才有它。

什么时候必须重跑并回填本页：

- 补完 T1-a / T1-b 的用例之后（每笔都要）；
- 新增或删除控件、或改了 `tests/` 下的文件名之后（脚本按文件名找用例，改名会静默变成 `∅`）；
- 台账结算前。

## 六、这一页不做什么

- **不判优先级**。`○` 的 238 格没有排序，哪个先补由 T1-a / T1-b 的台账行定（先补用户能看见的：
  禁用、焦点、键盘走查、主题切换、减弱动效）。
- **不当回归防线**。`●` 不等于「改坏了会红」，红绿验证在补用例时做。
- **不覆盖第三族**。`qxwindow` / `qxdock` 等不在本表范围，它们有自己的测试目录与口径。
