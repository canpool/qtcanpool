# 4.7 T1 覆盖矩阵：两族控件 × 八维

> 本文件是 **T1 的产物**，也是 **T1-a / T1-b 的作业单**。矩阵不证明「组件没问题」，它只标出
> **哪一格还没有人去过**。§二、§三 的两张表由 `scripts/t1_coverage.py` 从 `tests/` 现算，
> 不是手抄；补完用例后重跑脚本、换掉那两张表，再在台账 §九 记一笔。

## 零、怎么读这一页

### 五个记号

| 记号 | 意思 | 出处 |
| :---: | :--- | :--- |
| `●` | 有断言 | T1 的三句话之一 |
| `○` | 只测了默认态 | T1 的三句话之一 |
| `—` | 本件不适用 | T1 的三句话之一，理由写在同一行的「不适用理由」列 |
| `✗` | 不支持 | T1-c 追加的一格 |
| `∅` | 无用例 | **助手补的第五个记号，作者未拍板** |

多出 `∅` 的理由：台账那三句话是给**有用例的格子**定的。`FluentCard` 与 `FluentDivider` 没有专题用例
（前者只在 badge / reveal 的用例里当宿主，后者只在 button 的用例里当背景），把它们写成「只测了默认态」
是撒谎——默认态也没测过。所以单立一格，代价是记号从四种变五种。

### 「有断言」的判据

不看文件里有没有出现那个词，看**用例有没有自己把件推进那个状态**：`QTest::mouseClick` 打开菜单、
`QTest::key(Qt::Key_Right)` 走格子、`setEnabled(false)` 看它变灰、`QPalette` 换一套再看像素。
只读一次默认值、或注释里提到方向，都不算。

⚠️ **这一点必须写在最前面，免得 `●` 被当成保证**：`●` 只证明「有人去过」，不证明「那道门有锁」。
要证明后者得让用例红一次——先改坏实现看它红，再还原看它绿。那一步在 T1-a / T1-b 里做，
按台账规矩，**红不了的用例不进 T1**。所以本页的 `●` 是候选，不是结论。

### 六种「不适用」的理由

| 代码 | 适用件 | 理由 |
| :--- | :--- | :--- |
| 非控件 | `FluentReveal` · `FluentWindowMaterial` · `MaterialRipple` · `QxStateLayer` · `QxRingPainter` · `QxShadowPainter` | 派生自 `QObject` 或本身就是命名空间的绘制助手：不进焦点链、不产生可访问对象、无自身几何 |
| 纯装饰 | `FluentBadge` · `FluentDivider` · `MaterialBadge` · `MaterialDivider` · `MaterialSkeleton` | 不接收输入、不进入焦点链，也没有「被禁用」这一状态可画——把它们切成禁用，画面一模一样 |
| 浮出层 | `FluentCalendarFlyout` · `FluentContentDialog` · `FluentToolTip` | 由打开与关闭驱动，不是被启用的对象：禁用它无从画起，真正该变灰的是它托的那些件 |
| 只作指示 | `FluentProgressBar` · `FluentProgressRing` · `MaterialProgress` · `MaterialProgressRing` | 不接收指针、不进入焦点链（禁用态仍要管：变灰是看得见的行为） |
| 令牌 | `FluentShape` / `FluentType` · `MaterialShape` / `MaterialType` / `MaterialElevation` / `MaterialMotion` | 尺寸、颜色、高程等呈现常量，不含交互状态。时长档位是例外：它随「减弱动效」变，那一格照实记 |
| 不画动效 | 见各件「不适用理由」列 | 源码里既无动画类，也不问档位（`forDuration` / `motionFor`）：没有可减弱的东西。这一格若写「只测了默认态」，就会派出一条只能断言「什么都没动」的用例 |

**「不画动效」是从源码读出来的，不是猜的**：脚本按件名找 `src/libs/<层>/<件名小写>.cpp`，
命中 `QPropertyAnimation` / `QVariantAnimation` / `QAbstractAnimation` / `QTimeLine` / `forDuration(` / `motionFor(`
才算画动效。只有 `MaterialSnackbar` 用 `QTimer`，而它本来就有动画类，没有漏网的。

**证据优先于理论**：一个件若被写成了装饰，但用例确实把它点亮过（`MaterialBadge` 断言过焦点策略），
格子记 `●` 而不是 `—`。件能进那个状态，就说明它有那个状态。同一条也管「不画动效」：用例若真的
拨了减弱动效开关并看见变化，`●` 压过源码读出来的 `—`。

## 一、总数

| 层 | 行数 | 说明 |
| :--- | ---: | :--- |
| `qxfluent` | 38 | 含 checkable 合并行（`FluentCheckBox` / `FluentRadioButton` 共用一份用例） |
| `qxmaterial` | 40 | 含 checkable、`MaterialList` / `MaterialListItem` 合并行 |
| 共用层 | 4 | `QxControl`、`QxStateLayer`、`QxRingPainter`、`QxShadowPainter`；`QxControlAccessible` 的用例并入 `QxControl` 的无障碍格 |
| **合计** | **82** | 82 × 8 = **656 格** |

| 记号 | 格数 | 占比 |
| :---: | ---: | ---: |
| `●` | 331 | 50% |
| `○` | 99 | 15% |
| `∅` | 8 | 1% |
| `—` | 144 | 22% |
| `✗` | 74 | 11% |

**欠账 = `○` + `∅` = 107 格（16%）**。焦点欠账随 T1-a13 补完 qxmaterial 十六件焦点用例，从 33 件降到 17 件。这就是 T1-a / T1-b 的作业总量，从第一版的 249 格一路降到这个数：
T1-a1 把「不画动效」的 59 格判成 `—`，T1-a2 至 a11 逐件补断言、修缺陷，T1-a12 起把焦点列逐件补断言（键盘能否落到件上），每笔的增减记在台账 §九。

比第一版少的 120 格，来自十四处：

- **59 格在「减弱动效」那一列**：原先按「用例里没出现开关」记 `○`，把六十二件**根本不画动效**的件
  也算了进去——`FluentBadge`、`FluentDivider`、`FluentCard` 没有可减弱的东西，给它们补用例只能断言
  「没有动」，那不是覆盖，是凑数。判据补上「源码有动画类才算」，这 59 格归 `—`。
- **2 格**是 `FluentSlider` 与 `FluentRating` 的「禁用」：它们原先不画禁用态，现在画了，用例也跟上了。
- **7 格**是 `FluentComboBox`、`FluentNumberBox`、`FluentCheckBox`、`FluentDropDownButton`、`FluentSwitch`
  与两个进度控件的「禁用」：画得对，只是没人问过。
- **1 格**是 `FluentExpander`，它原先也不画禁用态。
- **2 格**是 `FluentGridView` 与 `FluentTreeView` 的「禁用」：delegate 一直在画（名字压到三十八分之一的
  透明度，图标走 `QIcon::Disabled`），只是没人为它写一句断言。
- **3 格**是 `FluentInfoBar`、`FluentBreadcrumbBar`、`FluentTeachingTip` 的「禁用」：三件都把点击拦住了、
  画面却一个字没说，禁用与启用**像素全等**——与滑块、评分、展开器同一类缺陷，现已各自淡出。
- **5 格**是五件纯装饰（两族的 Badge、两族的 Divider、`MaterialSkeleton`）的「禁用」：它们没有可被禁用的
  交互面，禁用与启用画得一模一样，补用例只能断言「什么都没变」，归 `—`。
- **3 格**是 `FluentAutoSuggestBox`、`FluentDatePicker`、`FluentTimePicker` 的「禁用」：三个文本框派生件
  一直跟着基类淡出，只是没人断言过——现在各有一条。
- **3 格**是 `FluentCalendarFlyout`、`FluentContentDialog`、`FluentToolTip` 的「禁用」，归 `—`：浮出层由
  打开与关闭驱动，本身不是被启用的对象，该变灰的是它托的那些件。
- **3 格**是 `FluentTabView`、`FluentToggleSplitButton`、`FluentCalendarView` 的「禁用」：三件都一直在画
  （逐页看 `isEnabled()`、承诺的字压到 `.4`、日历的整幅 `faded`），只是没人问过。
- **5 格**是 `MaterialSlider`、`MaterialTabs`、`MaterialSegmentedButton`、`MaterialStepper`、
  `MaterialAccordion` 的「禁用」：五件都是交互件（点击、拖拽、键盘各有用例），禁用与启用却是**像素全等**——
  与滑块、评分、展开器、信息条同一类缺陷，现已各自淡出。
- **5 格**是 `MaterialAvatar`、`MaterialBreadcrumbs`、`MaterialCheckBox / MaterialRadio`、`MaterialChip`、
  `MaterialSwitch` 的「禁用」：五件一直在画（字与图标各降一档、`ink` 乘 `.38`、整幅 `setOpacity`），只是没人问过。
- **7 格**是 `MaterialMenu`、`MaterialSelect`、`MaterialDrawer`、`MaterialTextField`、`MaterialDatePicker`、
  `MaterialTimePicker`、`MaterialAutocomplete` 的「禁用」：其中菜单是**按命令**淡出（`QAction` 禁用而不是整张
  菜单），选中项禁用时干脆不画箭头；字段一族只把**标签**压到 `.4`、框线与正文一字不动，两个 picker 与
  autocomplete 连标签都没有 ⇒ 禁用与启用**像素全等**。已改为整幅 `.38`，标签不再自带一道。
- **5 格**是 `MaterialFAB`、`MaterialSnackbar`、`MaterialProgress`、`MaterialProgressRing`、`MaterialList`
  的「禁用」：前四件只把交互拦下、或把动画停住，画面一个字没说（**像素全等**），现已各自淡出；列表本身不画
  东西，淡的是它那些行——行早就画了，只缺一句断言。
- **3 格**是 `MaterialCard`、`MaterialDialog`、`MaterialTooltip` 的「禁用」，归 `—`：卡片是纯容器、两个是
  浮出层，都没有「被禁用」这一面可画。
- **5 格**是 `MaterialSlider`、`MaterialSwitch`、`MaterialSnackbar`、`MaterialProgressRing`、
  `MaterialDialog` 的「减弱动效」：五件都走 `MaterialMotion::forDuration`（真跳板是 `QxTheme::motionFor`），
  源码里一直在问开关，用例却一次没断言过。各补一条：滑块与开关「动作即到位」、提示条「不再从下沿升起」、
  圆环「停止扫弧」（并反证开关放开后确实在转）、对话框「窗口不淡入」。

**「禁用」一列到此收干净**：`qxmaterial` 与 `qxfluent` 的 82 行里，只有 `FluentCard` 还是 `∅`（它没有专题
用例，属于「补用例文件」而不是「补一行断言」），其余都有断言或有不适用的理由。

「减弱动效」那一列剩下的真缺口只有五格，全在 `qxmaterial`：`MaterialDialog`、`MaterialProgressRing`、
`MaterialSlider`、`MaterialSnackbar`、`MaterialSwitch` 都有动画、也都在源码里问了开关，
只是**用例没有断言过**。

顺带两个量出来的基线，后面补用例时拿来自查：

- 81 个测试文件里有 **42 个**真的构造过非默认配色（`QPalette(...)` / `setPalette()` / 主题管理器），
  主题是唯一被成规模碰过的非默认维度——其余七维的 `●` 都不到这个密度。
- 两族的测试里 **没有一处**用过 `devicePixelRatio`；唯一的 DPR 用法在 `tests/qxwindow/native/`。

## 四、右到左与 DPR（T1-c）

### 右到左：不支持

| 项 | 内容 |
| :--- | :--- |
| 议题 | 两族要不要支持布局方向镜像（`Qt::RightToLeft`） |
| 决定 | **不支持** |
| 依据 | `src/libs/qxfluent` / `qxmaterial` / `qxcontrols` 三处搜 `RightToLeft` / `setLayoutDirection` / `isRightToLeft` / `LayoutDirection`：**0 命中**——没有一处读过方向。`QxControl` 之外的自绘几何按左起写死，例如 `fluentbreadcrumbbar.cpp:159` 的 `Qt::AlignLeft` |
| 处置 | 矩阵该列记 `✗`；`doc/pages/limitations.md` 加条目；**不造用例**（不假装支持） |

需要说清的分寸：走 `QLayout` 排出来的几何会跟着方向自动镜像，所以「整块面板左右对调」这类粗粒度行为
未必看得出来；坏掉的是**自绘的左右语义**——内边距起边、指示条贴哪一侧、箭头指向、进度从哪头长。
本条说的是后者没有实现，不是说前一种会崩。

### DPR：无用例，但**不**判不支持

八维里没有 DPR 这一列，T1-c 却要求一并判。实测两族用例 **0 处**碰过 `devicePixelRatio`，
像素断言全部在 `offscreen`（DPR = 1）下取样，所以 DPR ≠ 1 的显示没有任何用例走过。

但下「不支持」的判语需要证据，这里没有：两库的绘制都用逻辑像素，缩放交给 Qt 的绘制管线。
所以结论是**「没用例」**，不是「不支持」——差别在于前者是欠账（将来补一条 DPR = 2 的取样用例即可），
后者是能力缺口。这条留在 `limitations.md` 里按「未知」写，不按「已知缺陷」写。

## 五、怎么复算

```bash
python scripts/t1_coverage.py            # §二 的三张表
python scripts/t1_coverage.py --debt     # §三 的汇总与逐维清单
python scripts/t1_coverage.py --stats    # 只出记号计数，改用例后先看这个
```

脚本做三件事：按 `DRIVEN` 里的正则判「用例有没有主动把件推进那个状态」；按 `NA` 里的四类理由
把不可能有的格子判成 `—`；再按 `ANIMATES` 读一遍件自己的源码，把没有动画的件的「减弱动效」格
判成 `—`（这类理由不在 `NA` 表里，因为它是逐件算出来的，不是按类给的）。**行清单**（哪件、哪个用例文件、属于哪类理由）写在脚本顶部的
`FLUENT` / `MATERIAL` / `SHARED` 三张表里——新增控件时先加行，矩阵才有它。

什么时候必须重跑并回填本页：

- 补完 T1-a / T1-b 的用例之后（每笔都要）；
- 新增或删除控件、或改了 `tests/` 下的文件名之后（脚本按文件名找用例，改名会静默变成 `∅`）；
- 台账结算前。

## 六、这一页不做什么

- **不判优先级**。`○` 的 181 格没有排序，哪个先补由 T1-a / T1-b 的台账行定（先补用户能看见的：
  禁用、焦点、键盘走查、主题切换、减弱动效）。
- **不当回归防线**。`●` 不等于「改坏了会红」，红绿验证在补用例时做。
- **不覆盖第三族**。`qxwindow` / `qxdock` 等不在本表范围，它们有自己的测试目录与口径。
