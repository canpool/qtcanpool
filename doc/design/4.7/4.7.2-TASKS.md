## 一、这一版做什么

**一句话：开两个新的平台族风格库 `qxcupertino` 与 `qxharmony`（各「库骨架 + 令牌五轴 + 样板三件」），
把控件画廊从两页扩到四页，再收掉候选池里与这两个故事同线的五笔；`qxribbon` / `qxdock` 一行不碰。**

三块产物的性质不同，判据也不同：A / B 组是**新增目录**（只加，不改任何既有源码）、E 组是**验收面**
（故意改变截图）、F 组是**既有库的修复与重构**（行为可改，但要单独成笔、单独验）。

### 1.1 为什么两族同版

作者已定「4.7.2 引入两个风格」，这里只补三条执行理由，以及一条**容量退路**：

1. **同一套骨架做两遍，比拆两版省一次重定。** 两个库的四件东西完全同形——`_global.h` 的宏族、
   令牌五轴的命名与取值方式、`add_qtc_library` 的接线、测试套件的注册，以及 `qxcontrols` 提供的
   状态层 / 描边 / 阴影 / 无障碍桥。第二遍是照做，不是重新设计。
2. **金标只重基线一次。** `controlgallery.png` 现在是**一张**（默认页 fluent）；四页成形后按族拆成
   四张。拆两版就要重基线两次，而每次重基线都要人眼过一遍四张图。
3. **文档的改动是同一类，且都怕半成品状态。** `controls.md`「三个选项」→ 五个、版本表十列 → 十二列、
   架构图两支 → 四支。这些句子写一半（「现在有五个选项，其中两个还没做」）比写完更糟；
   拆两版就会有两版时间停在半成品状态上。

⚠️ **容量退路（STYLES §七 原文，不是我新加的）**：若同版显得过挤，**Cupertino 先开张、HarmonyOS
顺延 4.7.3**——一族一个 patch，两族不互斥。真要顺延，**先问作者**（该稿写明「不自行决定」）。

### 1.2 为什么是 patch，不是 minor

- `versions.md` 的版本表原文：「新增能力（加类 / 加函数 / 加带默认值的参数 / **新增库**）⇒ **patch +1**」。
  ⚠️ 不要拿 4.7.0 当先例论证这件事：4.7.0 是**按版本序（K34）作为 minor 立项**的版本（它的定位就是
  「fluent / material 两个 widget UI 库」），不是「因为开了三个库才 minor」。开库本身只够 patch——
  本条的依据是版本表那一行字，不是某次结算的形状。
- 本期不改签名、不删 API、不改名 ⇒ K36 的三个 minor 触发器（改签名 / 删 API / 改名）一个都不挨，
  K37 的收口判据也不受影响。F 组里有**行为变更**（F3 / F4），按 Q11（`4.7.1-TASKS.md` §六）走 patch
  + 库 `CHANGELOG` 单独成条。
- 两个新库的初始号 **`0.1.0`**（照 4.7.0 §七.5「三个新库的初始版本号」）。

## 二、任务分解

### 2.0 两族共用的骨架（一次定义，两次照做）

每个新库的第一笔**只开骨架、不带任何控件**——骨架要能独立编过、独立进 ctest 套件（只有一个令牌测试）。
4.7.0 的 `qxcontrols` 就是这么开的（`0.1.0` + "The library opens."）。

⚠️ **骨架笔里必须至少有一个 `.cpp`，所以令牌与骨架同笔落**：`add_qtc_library` 不补任何占位源文件
（`cmake/QtCanpoolAPI.cmake:175`，`SOURCES` 原样进 `add_library`），而只有头文件的目标 CMake 定不了
链接语言（`Cannot determine link language for target`）。令牌的 `.cpp` 正好是这个文件，也是这一笔唯一
可测的东西。

| 文件 / 位置 | 内容 | 体例来源 |
| :--- | :--- | :--- |
| `src/libs/qx<lib>/qx<lib>_global.h` | 命名空间 `Qx<Family>` / `QX_<LIB>_EXPORT` / 三件版本宏 / `QX_DECLARE_PRIVATE` 宏族 / `QX_<LIB>_DEPRECATED_SINCE` | `qxfluent_global.h` 全文照抄换名（`DISABLE_DEPRECATED_BEFORE` 的默认值必须是 `(0,0,0)`，那里有一条注释讲了为什么不能是当前版本） |
| `src/libs/qx<lib>/<lib>tokens.{h,cpp}` | 令牌五轴：Shape / Type / Elevation / Motion / Color（第五轴的范围见 Q3：**只放系统语义色**，surface / text / accent 仍走 palette） | `fluenttokens.{h,cpp}`：枚举 + 一个取值函数 + 表驱动，注释里每个值旁边写「为什么是这个数」 |
| `src/libs/qx<lib>/CMakeLists.txt` | `add_qtc_library(qx<lib> VERSION 0.1.0 DEFINES QX_<LIB>_LIBRARY PUBLIC_DEPENDS qxcontrols Qt5::Core Qt5::Gui Qt5::Widgets SOURCES ...)` | `qxmaterial/CMakeLists.txt`（它没有条件依赖，比 qxfluent 干净） |
| `src/libs/qx<lib>/CHANGELOG` | 顶端 `0.1.0` + `Feature` + "The library opens." | `qxcontrols/CHANGELOG` 第一条 |
| `src/libs/CMakeLists.txt` | `option(WITH_QX<LIB> "Build qx<lib> library" ON)` + 一段 `add_subdirectory`（带一句「它读 `qxcontrols`，不认识另外三族」的注释） | 同文件里 `qxmaterial` 那段 |
| `tests/qx<lib>/auto/main.cpp` | `TEST_RUN_ALL()` 聚合（照 `tests/qxmaterial/auto/main.cpp`） | 同上 |
| `tests/CMakeLists.txt` | 一段 `file(GLOB ... CONFIGURE_DEPENDS ...)` + `add_qtc_test(tst_qx<lib> ...)` | 同文件 `tst_qxmaterial` 段（GLOB + `CONFIGURE_DEPENDS` ⇒ 加 `tst_*.cpp` 就自动进场） |

**依赖方向**：`qxtheme ← qxcontrols ← qxcupertino / qxharmony`。两个新库**互不依赖**，也不依赖
`qxfluent` / `qxmaterial`（照 `architecture.md` 的「两套控件集互不依赖」）。

**命名**（Q2 已裁：照此）：库目录 `qxcupertino` / `qxharmony`；命名空间 `QxCupertino` / `QxHarmony`；
类 `Cupertino*` / `Harmony*`；文件 `cupertino*` / `harmony*`；宏 `QX_CUPERTINO_*` / `QX_HARMONY_*`。
⚠️ **不用完整产品名 `HarmonyOS`** 进代码、文件名与类名（STYLES §5.2 的商标谨慎），文档里讲设计语言时
可以写「HarmonyOS 设计语言」。

#### A2 · 令牌五轴（与 A1 同笔）

| :--- | :--- | :--- | :--- |

⚠️ 表里的数值是**草案**：A2 落地时按公开规范核对一遍，写进 `cupertinotokens.h` 的注释后以代码为准。
**不许出现**「抄某个实现的常数」——4.7.0 §1.3-6 只允许读规范与公开文档。

判据：`tst_cupertinotokens.cpp` 断言五轴的每一档都落在表里、越界索引返回 0 / 无效色而不是崩溃
（照 `fluenttokens.cpp` 的越界处理）。

**A1 + A2 执行记录（2026-10-23，`feat(cupertino)` 一笔）**：骨架与五轴同笔落地——`qxcupertino_global.h` /
`cupertinotokens.{h,cpp}` / `CMakeLists.txt` / `CHANGELOG`（顶端 `Unreleased`，结算改名 `0.1.0`）/
`src/libs/CMakeLists.txt` 的 `option` 与 `add_subdirectory` / `tests/qxcupertino/auto/{main,tst_cupertinotokens}.cpp` /
`tests/CMakeLists.txt` 的一段。`ctest` **21 → 22**，两腿 22/22。四处与草案不同，都以代码为准：

1. **第五轴是「角色 × 两种切法」**，不是「角色」：`color(Role, bool onDark = false)`。语义色不是单值——
   同一个绿在明面和暗面上是两个绿，只给一个就有半边是错的。五个角色取系统公开的明暗两版值
   （`0x007AFF / 0x0A84FF` 一组），不取主题强调色。
2. **动效四档只落到三级**：`motionTiers = {0,1,2,2}`，Gentle 与 Entrance 共用最长一级。草案把
   100 / 200 / 300 / 400 写成四个互不相同的档，但共享阶梯只有三级，硬拆会造出「两个毫秒数在同一档里
   打架」的假差别——tier 才是被重定时与归零的东西，这是那条映射的直接后果。两条曲线定成对称的
   （`InOutCubic` / `InOutQuint`），作为「去和回一样快」这条辨识点的可核对形态。
3. **高度轴的值不是「核对过 HIG 的数字」，是本族的读数**，理由写进了 `cupertinotokens.h` 的注释：
   宽、淡、贴得近（每条 `yOffset < blurRadius / 2`，这一条进了测试）。⚠️ 这句是**声明一个取舍**，
   不是声明合规：本项目没有可靠渠道逐条核 HIG 内部数值，写一个数字再声称「规范如此」比说「这是
   本族的读数」更糟。作者目检时按 §五「像不像没有判据」那一行看。
4. **档位名英文化**：`Quick` / `Normal` / `Gentle` / `Entrance`（草案写的是「快 / 常规 / 缓 / 入」）。
   标识符一律英文是仓库体例，中文留在注释与文档。

判据：① 两腿 `22/22`；③ `Q_OS_` / 字体 / `tools/themes` 全空；⑥ 单文件最长 `cupertinotokens.h` 180 行
（`.cpp` 146）；⑦ clang-format 干净。② 本笔全 `A`；⑤ 五轴的 `Color` 要到 A3（开关的「开」）才非零——
按 §V「每族三件落完后跑 ②⑤ 一次」，本笔不单独跑。

#### A3 · `CupertinoSwitch`

- **辨识点**（这一句就是它的验收说明）：轨道是**细长胶囊**，关灰开绿，圆形滑块白底带一层浅影，
  滑块跨过中点时才变轨道色——不是「走到一半就变色」的渐变。
  ⚠️「开」取 `CupertinoColor::Green`（Q3 裁「语义色进第五轴」），**不是** `accentColor()`：主题换成
  soft / slate 时它仍是那个绿，这才是 Cupertino。
- **尺寸**：轨道 51×31 逻辑像素（HIG 的开关尺寸），滑块直径 27、四周 2 像素内缩。
- **动效**：位置与轨道色同一个 200ms 缓出；`QxTheme::isMotionReduced()` 为真时**直接落位**。
- **测试**：`isOn()` / `setOn()` 往返、点击切换、键盘空格、越界点击不变、减弱动效下终点正确
  （用 `QSignalSpy` 等 `toggled`，不等动画）。

- **父项点按**：`activate()` 先翻 `expanded` 再导航（`SelectsOnInvoked`）。
- **折栏 flyout**：`NavigationFlyout`（`Qt::Popup` + 半透明圆角面板，平铺列可见后代并带缩进）。

**G1 执行记录（2026-10-23，`fix(cupertino)` 一笔）**：`cupertinosegmentedcontrol.cpp` 加 `pillFace()`、
`painter->setBrush(Qt::white)` 换成它，测试加 `thePillAndItsLabelStayApartOnADarkPage()` 一条。

根因是**药丸与它的墨各跟各的一条线**：药丸写死 `Qt::white`，墨读 `textColor()`（= `QPalette::WindowText`，
深色主题下是浅墨）。浅色下两条线碰巧一致，深色下就成了白底白字——选中段读起来是一个空格子。
修法**不是**把墨改成恒深（那只是让白药丸在深色页上继续刺眼），而是让药丸也跟明暗走：浅色仍是白（家族
的白），深色取 `Gray` 令牌按 `0.55` 铺在页面上，正好比轨道亮一档——药丸是「抬起来的面」，在任何一页上
都得比它躺的那一行亮，白只在其中一页上是那一档。实测 soft-dark 下：页面 `#1F1F1F` · 轨道 `#464647` ·
药丸 `#626264` · 墨 `#F3F2F1`（对比 5.0:1）；soft-light 下药丸仍是 `#FFFFFF`、轨道 `#D3D3D5`（不变）。

判据：新用例把调色板换成深色（`Window #3A3A3A` / `WindowText #F3F2F1`）后量两件事——药丸比页面亮
（≥ 15 级，读像素）与墨和药丸拉开 ≥ 60 级（**算两个颜色，不读字形**）。后半条本该读像素，但 Qt 5 的
offscreen 平台一个字形也不画（读数 `111 on 111`，整块只有药丸），读像素的版本在 Qt 5 腿上是假红；改成
算颜色之后两腿一致，而判据的意思没变——要量的本来就是「墨与面拉不拉得开」，不是「字画出来没有」。
**回退验证**：把 `pillFace()` 换回 `Qt::white` 时，像素版报 `13 apart: 255 on 242`（正是作者看到的那
一格），颜色版报 `12 apart: 255 on 243`。

**G2 执行记录（2026-10-23，`fix(harmony)` 一笔）**：`harmonyslider.cpp` 加 `kRailFromBottom` /
`bubbleHeight()` / `drawingHeight()` 三个说法，`sizeHint()` 与 `minimumSizeHint()` 的高度都改成
`qCeil(drawingHeight())`；测试加 `theBubbleIsWholeAtTheHeightTheSliderAsksFor()` 一条。

根因是**高度是一个凑出来的整数（26 + 24 = 50），而气泡的高度是一个字体答案**。气泡画在手柄上方
（`handle.top() - 2 - bubbleHeight`），控件又画不出自己的矩形，所以高度不够时被切掉的是气泡的顶——字号
越大切得越多，而原来 `minimumSizeHint()` 的高度只有 34，一个把它压到最小的布局会把气泡切掉大半。
现在两处都从 `Caption` 的行高推：`drawingHeight() = kRailFromBottom + 手柄半高 + 间隙 + 气泡高 + 1`，
窄一点允许（轨道是条线，短也还是轨道），矮一点不允许。

⚠️ 第一版判据写成 `qRound(line) + 6 - 1`（留一行容差），**本机放过了原 bug**：本机 `Caption` 行高 16，
原高度 50 时气泡只差 1 像素。容差去掉后（`+ 6`）才抓得住——这条记在这里，因为「差一行」正是这种缺陷
的典型量级，容差一给就看不见了。

判据：按住手柄后从控件顶往下找第一行蓝色，量「气泡顶到气泡底」的高度，要求 ≥ `Caption` 行高 + 6；
并钉住 `minimumSizeHint().height() == sizeHint().height()`。**回退验证**：把两个 hint 换回 50 / 34 时
第二条先红，单独去掉它后第一条红。
