## 二、A3 · legacy ribbon 物理移除（本次执行）

### 2.1 影响面勘察（实测结论）

**结论：影响面极小。** 全树搜索 legacy ribbon 的**真实使用者只有一个 demo**，而且它**根本不在 CMake 构建里**。

| 引用方                                            | 性质                                  | 处置                       |
| :--------------------------------------------- | :---------------------------------- | :----------------------- |
| `src/libs/qcanpool/ribbon*`（13 文件）             | 被移除对象本身                             | **删除**                   |
| `demos/qcanpool/fancyribbon/`                   | **唯一真实使用者**；仅存在于 qmake 的 `qcanpool.pro` 中 | **删除**（连同 `.pro`）        |
| `src/libs/qcanpool/CMakeLists.txt`              | `option(QCANPOOL_CONFIG_RIBBON)` + `if` 块 | **删除选项与扩展块**             |
| `src/libs/qcanpool/qcanpool-lib.pri`            | qmake 侧列出这 13 个文件                    | **删除对应区段**（否则 qmake 构建断裂） |
| `src/libs/qcanpool/qcanpool.h`                  | 注释里以 legacy ribbon 举例说明 `QCANPOOL_DEPRECATED_X` | **改注释**（宏本身保留）           |
| `demos/qcanpool/qcanpool.pro`                   | `SUBDIRS` 含 `fancyribbon`             | **删除该子项**                |
| `projects/staticlink/staticlink.pro`            | `QCANPOOL_CONFIG_RIBBON = 0` + 同名冲突注释 | **简化**（冲突已消失）            |
| `src/libs/qcanpool/fancy*`/`tiny*`/`mini*`      | 经核实**零依赖** ribbon 符号                 | 不动                       |
| `src/libs/qxapp`、`src/libs/qxribbon`、`tests/qxribbon` | 均为 `QxRibbon::` 同名类，**非** legacy      | 不动                       |

> ⚠️ `staticlink.pro` 里原有注释 `There are conflict ribbon files with the same name in qxribbon and qcanpool` —— 这正是债务 D13 的原始现场记录。移除后**同名冲突彻底消失**。

## 三、A1 / A2 / A4 · legacy 收敛收口

### A1 迁入 `qxapp`（通用控件）

| 来源                                                                     | 去向                     | 备注                     |
| :--------------------------------------------------------------------- | :--------------------- | :--------------------- |
| `FancyWindow`                                                          | `qxapp`                | 应用窗口，与 AppShell 能力合并    |
| `FancyDialog`                                                          | `qxapp`                | 通用对话框                  |
| `FancyToolButton`                                                      | `qxapp` / `qxcore` 样式层 | 通用按钮外观                 |
| `ExtensionButton`、`MenuButton`、`MenuAccessButton`                        | `qxapp`                | 通用小控件                  |
| `TinyTabBar`、`TinyTabWidget`、`TinyNavBar`                              | `qxapp`                | 轻量 Tab / 导航（通用性高）      |

**规则**：迁入时**改名入 `QxApp` 命名空间**（去掉 `Fancy`/`Tiny` 前缀），并在 `qcanpool` 保留同名转发类（继承 + 构造转发）一个版本，避免二次破坏。

### A2 下线（与 `qx*` 重叠、无独立价值）

| 控件                                                    | 理由                                  |
| :---------------------------------------------------- | :---------------------------------- |
| `QuickAccessBar`                                      | 已被 `RibbonQuickAccessBar` 取代         |
| `FancyTitleBar`、`WindowLogo`、`WindowToolBar`           | 与 `qxwindow` / `qxribbon` 窗口方案重叠     |
| `MiniTabBar`、`MiniTabWidget`                          | 与 `Tiny*` 系列重叠                      |
| `FancyBar`、`FancyTabBar`、`FancyTabWidget`             | 与 `Tiny`/`Mini` 三选一后决定（见存废表"评估"档）   |

### A4 补 `deprecated` 标注

对 A2 判定"观察后下线"但暂不删除的遗留头补齐 `QCANPOOL_DEPRECATED_X`（当前 **18 个 `fancy*`/`tiny*`/`mini*`/`menu*`/`window*` 头一个字都没标**），使「编译告警即迁移点」成立。

## 四、B 组 · 质量门禁补齐

### B1 覆盖率报告

- CMake 新增 `option(WITH_COVERAGE)`：GCC/Clang 下加 `--coverage`，链接加 `--coverage`；**不要**污染 Release 默认配置。
- CI：在 `ubuntu-latest / Qt 6.8.1` 腿追加覆盖率构建 + `lcov` 生成 HTML，产物上传为 artifact。
- **K8 决策**：**先出报告、不设阈值**；连续 1~2 个版本稳定后再议是否设门禁。

### B2 clang-tidy + 消毒器

- 新增 CI 作业 `clang-tidy`：只跑 `src/libs`（`compile_commands.json` 由 CMake 导出，需 `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`）。
- 起步策略：**先只报新增告警**（或对既有告警设 `--line-filter` / 基线文件），避免一次性引入上百条噪声。
- 把仓库已有的 `WITH_SANITIZE` 真正用起来：CI 增加一条 `ASan+UBSan` 的 Linux Debug 构建腿（可只构建不跑测试，或跑 `ctest`）。

### B3 `qxwindow` 自动化测试

- 新建 `tests/qxwindow/auto/`（`main.cpp` + `tst_*.cpp`），在 `tests/CMakeLists.txt` 用 `add_qtc_test(tst_qxwindow DEPENDS qxwindow ...)` 注册。
- 优先覆盖**平台无关逻辑**：窗口上下文选择、尺寸/命中几何计算、`QX_WINDOW_CONFIG_NATIVE` 开关下的降级路径。
- 原生后端（Win/macOS/X11）只做"能构造、不崩"级别冒烟，避免 CI 平台差异导致脆断。

### B4 demo 截图回归（可选）

- `QT_QPA_PLATFORM=offscreen` 下启动 `RibbonDemo`/`DockDemo`，截图与 golden image 比对。
- **易碎**，建议置于 3.1 末尾且**允许失败不阻塞**；先只做 1 个 demo 验证可行性。

## 六、风险与注意

- **A3 是破坏性变更**：`qcanpool` 的 legacy ribbon 源码兼容被打破。必须在 `CHANGELOG` 显著标注，并确认存量用户（如 MyCAD）已完成迁移。K7 已由作者确认放行。
- **qmake 侧必须连带修改**：`.pri` 若继续列出被删文件，qmake 构建会直接断裂。这属于"维持冻结构建可用"的必要维护，不是新增特性。
- **覆盖率/静态分析起步噪声**：按 K8 不设阈值；clang-tidy 从"仅新增告警"起步。
- **不要为凑覆盖率写无效测试**（K8 精神）。

### B3 · `qxwindow` 自动化测试（已完成）

新增 `tests/qxwindow/auto/`（`main.cpp` + `tst_qxwindow.cpp`），在 `tests/CMakeLists.txt`
以 `add_qtc_test(tst_qxwindow DEPENDS qxwindow ...)` 注册。8 个用例，全部针对
**后端无关**的逻辑：`accessorsBeforeSetup` / `setupOnlyOnce` / `titleBarRoundTrip` /

`captionClassName` / `windowAttributes`。

> 需要真实窗口管理器的部分（拖拽、系统菜单、Win10 边框 workaround）**刻意不测**——
> 它们随平台而异，只会制造 CI 噪声。

**验证**：8/8 通过；并做了**证伪验证**——临时注入一个必失败的断言，ctest 确实变红
（`CTEST_RC=8`），确认套件不是空跑。clang-format 门禁 **350 文件**通过。

**顺带修掉一个真实缺陷**：`WindowAgentBasePrivate` 的窗口上下文原本只在 `setup()` 里创建，
而 `WindowAgentBase` / `WindowAgentWidget` 的**所有访问器都会解引用它** —— 因此
`WindowAgentWidget agent; agent.titleBar();` 会**解空指针崩溃**。改为在
`WindowAgentBasePrivate::init()`（即构造期）创建上下文，`setup()` 只做 `m_context->setup(host, delegate)`。
独立提交，便于单独回滚。
