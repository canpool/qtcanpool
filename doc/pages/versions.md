# 版本对照

**项目版本**（tag 打在它上面）是发布列车号；**每个库另有自己的版本号**，两者互不绑定（K11）。
每次项目发版**结算一次**：这一批里**有修复或增量的库才前进号**，没动的库保持原号。

## 项目版本怎么走（K36，2026-10-22 作者拍板）

⚠️ **本项目的 `patch` 含新增能力**——加类、加函数、加带默认值的参数、甚至新增库，都进 patch。
这与「patch = 只修 bug」的常见约定不同，读这张表时不要按字面 semver 去理解。

| 情形 | 项目版本 |
| :--- | :--- |
| 新增能力（加类 / 加函数 / 加带默认值的参数 / 新增库）、修复、**内部**重构 | **patch +1**（常态） |
| 要废弃某个 API | **先标 `QX_<LIB>_DEPRECATED_SINCE`**，patch +1；**不能直接删** |
| 改签名 / 删 API / 改默认行为（且不是修缺陷） | **minor +1**（唯一的 minor 触发器） |

**兼容性由项目版本承诺**：同一个项目 minor 系列（如 `4.7.x`）内，所有库的公开 API
只增、不减、不改签名，默认行为不变。破坏性变更只在项目 minor 递增时发生。
库号仍是 0.x、仍按 K11 独立演进（只回答「这个库本期动了多少」），**不跳 1.0**——
留到 5.0（K30 移除 Qt 5）再统一考虑。完整规则见
[`doc/ROADMAP-3.x.md` 附录 B](https://github.com/canpool/qtcanpool/blob/master/doc/ROADMAP-3.x.md)。

判据是「**这个库本期有没有修复 / 增量**」，不是「头文件动没动」：纯 `.cpp` 修复照样进 patch，
而删版本守卫、删 `header.list` 这类**构建接线**只记录、不进号。所以 3.0 → 3.3 项目版本走了四位，
好几个库却一位未动——这不是遗漏，是在声明「这些库本期没有变化」。推进规则的完整约定
（含发布时的操作步骤）见
[`doc/ROADMAP-3.x.md` 附录 B](https://github.com/canpool/qtcanpool/blob/master/doc/ROADMAP-3.x.md)。

## 各行为什么动 / 为什么不动

### 3.0.0 – 3.3.0：四行全未动

3.x 的四行里库号全未动，积压到 4.0 一次性结清：`qxcore` 拿走 **0.1.1**（3.2 就落地的
@ref QxCore::QxTranslator 一直挂到那时），`qxapp` 拿走 **0.1.0**（Toast / 属性编辑器 / 设置对话框 /
工作区 / 状态栏进度，加上 4.0 的插件上下文）；新增的 `qxplugin` 从 **0.2.0** 起。
`qxtheme` / `qxwindow` / `qxribbon` / `qxdock` 到 4.0 **仍是一位未动**——这不是遗漏，
是在声明「这些库本期没有接口变化」（K11）。

### 4.1.0 与 4.1.1

**4.1.0 那一行与 4.0.0 完全相同**，不是遗漏：本期改动全在 `.cpp` 与注释里
（两个修好的缺陷、16 条自写欠账的处置、一张已知限制页），**公开头文件一个字节没动**。
版本号是对接口的声明，接口没变就不该动（K11 / 附录 B）。

**4.1.1 只前进了一个库**：`qxribbon` 到 **0.10.2**——`ribboncontainers.h` 里
`RibbonGridContainer::enterEvent` 的声明按 Qt 版本分支了（Qt 6 的形参是 `QEnterEvent *`，
用 Qt 5 的签名在那边**不是重载而是隐藏**），这是本批**唯一的头文件改动**。
同批的 `qxdock` 修复只动了 `.cpp`，按当时「有 API 改动才前进号」的读法**保持 0.2.0**，
它的说明写在库自己的 `CHANGELOG` 的 `Unreleased` 分节里（K24）——「版本号回答动了没有，
库级 CHANGELOG 回答动了什么」，两者分工不同。（这条读法在 4.4.2 被推翻，见下。）

### 4.2.0：两个库因弃用进 minor

`qxwindow` 到 **0.2.0**、`qxribbon` 到 **0.11.0**，两处都是**弃用**
（`WindowStyleAgent` 按 K26、`FramelessHelper` 按 K27；**前者已在 4.3 删除**）。按附录 B，弃用是
「接口契约发生了变化性调整」，所以走 `minor` 而不是纯增量的 `patch`。`qxribbon` 同期还给
`RibbonStyleOption` 加了三个 setter，单算只是 patch，但同一期发生了弃用 ⇒ 取较高的 minor。
`qxdock` 本周期唯一的头文件改动（`dockautohidecontainer.h`）**只是一段注释**（A13），
按附录 B 不算 API 改动 ⇒ **保持 0.2.0**，它的说明继续留在库级 `CHANGELOG` 的 `Unreleased` 分节里。
其余四个库本期公开头文件一个字节没动，因此**一位未动**。

### 4.3.0：七个库全部前进，本项目第一次

原因只有一个：**A8 修的那个弃用闸门，七个库各有一份**（`QX_<LIB>_DEPRECATED_SINCE`
对"已经发生的弃用"恒返回假，见根 `CHANGELOG`）。按附录 B，`patch + 1 = 纯增量或修复`，
于是它给七个库各带一个 patch；其中 `qxribbon` / `qxwindow` **另外删了公开 API**
（前者两个导出类、后者一整个公开头），按"契约变化 ⇒ minor"压过 patch，分别到 **0.12.0** 与 **0.3.0**。
⚠️ 这一步是**判断**而非算术：「`_global.h` 只此一处改动算不算动」可以两说（4.0 那次 `qxdock`
也只改了 `_global.h` 而**没有**进号），差别在于 **4.0 那次改的是版本号宏这个"镜像"本身（记账），
本次改的是一个宏的语义（行为）**——判据写在 `doc/design/4.3-TASKS.md` 的 D1 一节里。

### 4.4.0 – 4.4.2

**4.4.0 前进了三个库，全是纯 `.cpp` 修复**：`qxwindow` 0.3.1、`qxribbon` 0.12.1、`qxdock` 0.2.2，
没有一处导出符号变动——按附录 B「修复 ⇒ patch」进号。

**4.4.1 那一行没有加粗的格子**：那一期 `src/libs` **一行代码都没动**（改动全在 examples、tests
与文档里），按附录 B「本期没有改动的库保持原号」⇒ 七个库都不动。

**4.4.2 前进了四个库**，判据不是「头文件动没动」而是「**这个库本期有没有修复或增量**」
（附录 B：`patch + 1` = 纯增量或修复）——4.4.0 的 `qxribbon` / `qxdock` / `qxwindow` 就是
**三个纯 `.cpp` 修复照样各进一个 patch**，`release.md` 也照此执行。⇒ `qxcore` / `qxribbon` /
`qxdock` / `qxapp` 本期各有修复 ⇒ 各进一个 patch；`qxtheme` 与 `qxwindow` 各只删掉一个
「低于 5.15」的版本守卫（**构建接线**，附录 B 的现成例子是删 `header.list`：记一笔、不进号），
`qxplugin` 零改动 ⇒ 三个保持原号。四个动号的库，其 `Unreleased` 分节随进号改名（K24）。
⚠️ 这条判据纠正了 4.1.1 当时的读法，也纠正过更早一次把它读反的结算（`release.md` 已改写）。

### 4.5.0：六库进 minor，一库保持

**六个库全部走 minor**（K26：删除 / 改签名只进 minor），每库都有 API 的增、删或签名变更：

- `qxcore` 0.1.3 → **0.2.0**：`QxSettings` 整组读写与 `QxTranslator::translate()` 两个新 API，
  加 `setVersion()` 上报修复；
- `qxtheme` 0.1.1 → **0.2.0**：E7 删 `Theme` 枚举与六个自由函数、`setStyleSheetFile()` 删、
  `palette(Theme)` 与 `setStyleSheet()` 改签名，加 E1 平台强调色与覆盖；
- `qxribbon` 0.12.2 → **0.13.0**：B12 删 `RibbonTheme` 与窗口主题三件套、A5 四个样式值
  与谓词改名，加 B 组一整批新功能与五处修复；
- `qxdock` 0.2.3 → **0.3.0**：C9 `DockWindow` 不再自带样式表（行为变更），加 C2/C3/C5/B2
  新功能与自动隐藏覆盖层修复；
- `qxapp` 0.1.2 → **0.2.0**：A1 `QxNavBar` → `QxNavTabBar` 改名，加 D1/D2/B2 与便捷注册；
- `qxplugin` 0.2.1 → **0.3.0**：E5/E6 懒加载与可查询的依赖图两个新 API。

**`qxwindow` 保持 0.3.1**：本期只有注释英化与 BOM 清理两个提交碰到它，无修复 / 增量。
它的 `Unreleased` 分节因此继续悬挂（4.4.2 起就是如此）——里面唯一条目是 4.4.2 周期
`559ff4d3` 写下的版本守卫删除记录，待该库将来进号时并入。
