# 主题生成

`res/themes/*.css` 是**生成物**，不要手改 —— 跑一遍脚本就会被覆盖。
`res/themes/<family>_<scheme>.json` 同样是生成物：**同一个 `PALETTES` 条目的数据版**，
随 css 一起写出。css 里角色已经被替换成具体色值，读不回来；json 留给「画在样式表之外」
的库（qxdock 的自有片段就是第一个消费者），经 `QxThemeInfo::colors` 送到应用层。
一套主题由五部分相加而成：

| 文件 | 作用 |
| :--- | :--- |
| `menu.css` | 菜单的**几何**（QMenu/QMenuBar），两套骨架共用一份源：菜单栏与菜单行的高度由表说了算，不由平台样式留下什么算什么 |
| `skeleton_light.css` | 浅色骨架：只描述 Ribbon 部件。标准控件交给平台样式 + 浅色调色板 |
| `skeleton_dark.css` | 暗色骨架：除 Ribbon 外**还要重画标准控件**（暗色下平台样式会忽略调色板，否则下拉框、树、滚动条仍是浅色） |
| `chrome_<family>.css` | 家族的**结构**差异：页签怎么表示选中、圆角、页签条与页面之间有没有分隔线、强调色用在哪 |
| `res/dockstyle/base.css` | dock 的那半张表（`QxDock--*`）。**源只有这一份**：它对明暗无话可说——两张骨架说同一套结构，差别只在令牌填进什么值——而 qxdock 在运行时还要读同一份，给没装主题的应用当回退表 |
| `build_themes.py` 里的 `PALETTES` | 该家族的**颜色**角色 |

三者拼起来 = `res/themes/<family>_<scheme>.css`，每个家族 × 明暗两套各一份。
家族清单以 `build_themes.py` 的 `FAMILIES` 为准（当前 classic / soft / flat /
slate / accent）。

> **两份骨架是同一份主题的两种说法，不是两份独立的表。** 同一个控件、同一个状态，
> 两边都要写；改一侧就去另一侧找对应规则。
>
> 只有**颜色**可以按明暗反转（亮色下字形是深色，状态填充只能浅；暗色下字形是浅色，
> 可以填实心强调色 —— 见两个文件开头的说明）。**与明暗无关的东西必须一致**：
> `padding`、`width`/`height`、`font-weight`、`margin`。它们决定了 ribbon 量出来的
> 尺寸，只写在一侧，同一个窗口在两套主题下就会算出不同的宽度、行高和页签宽度。
>
> 长度不同是正常的：暗色骨架还要重画标准控件（浅色主题把它们交给平台样式）。

> 只换颜色不足以成为一个家族。几套主题如果共用同一份骨架、只改色板，选相邻一档的
> 深灰看起来就是"完全一样" —— 这正是为什么要单独有 `chrome_*.css`。各家族在
> **四条轴**上同时不同，所以不看名字也能分：
>
> | | 条与页的明暗 | 选中态 | 分隔与盒子 | 文件按钮 |
> | :--- | :--- | :--- | :--- | :--- |
> | classic | 条灰、页白 | 抬高的白卡片（直角、带边） | 分组竖线 + 大按钮有框 | 实心强调色方块 |
> | soft | 条白、页灰（反过来的） | 开进正文的圆角开口（无边框） | 全无 | 实心强调色、圆角 |
> | flat | 同色，一层 | 强调色 2px 下划线 + 文字取强调色 | 全无 | 实心强调色方块 |
> | slate | 条深灰、页白 | 留在条上，只加顶部 1px 强调线 | 分组发丝线、无框 | 无填充，仅强调色文字 + 下划线 |
> | accent | 条白、页白 | 强调色**实填**选中标签（白字） | 全无 | 实心强调色方块 |

## 做一套新主题

1. **定家族名**，例如 `acme`。把 `chrome_acme.css` 放在本目录，只写这个家族
   与其它家族**不同**的地方（选中态、圆角、分隔线）。没写的部分沿用骨架。
2. 在 `build_themes.py` 里加两条调色板：`("acme", "light")` 与 `("acme", "dark")`，
   把下表的角色填满（每个 palette 都要填全，否则脚本会报缺少哪个角色）。
3. 把 `acme` 加进 `FAMILIES`，以及 `FAMILY_NOTES`（会写进生成文件的头注释）。
4. 跑：

   ```bash
   python3 tools/themes/build_themes.py
   ```

   然后 `git diff res/themes/` 复核，把生成的文件一起提交。

5. 要让应用能用：`res/themes.qrc` 里加条目，应用侧 `QxThemeManager::registerTheme()`
   给一个 id（约定 `<family>-<scheme>`，如 `acme-dark`，`dark` 传 `true`）。

## 颜色角色

| 角色 | 用在哪 |
| :--- | :--- |
| `text` / `text-muted` / `text-on-fill` | 主文字 / 次要文字 / 压在强调色块上的文字 |
| `surface` / `surface-alt` / `surface-sub` | Ribbon 条（chrome，页签坐在上面）/ 次级面 / 更次一级（子控件） |
| `body` | **正文档位**：页签下方的 ribbon 页面。与 `surface` 分开，才可能让某些家族"条浅页深"、另一些"条深页浅" |
| `state-rest` / `state-hover` / `state-pressed` / `state-pressed-deep` | 常态填充 / 悬停 / 按下 / 按到底 |
| `border` / `border-strong` | 发丝线 / 需要看清的边（分隔线、输入框边） |
| `accent` / `accent-hover` | 强调色：焦点边、下划线、悬停加深 |
| `accent-text` | 强调色当**文字或字形**压在中性面上（选中页签的字、文件键的字形）。亮色取深一端、暗色取亮一端，否则 4.5:1 不够 |
| `accent-fill` / `accent-fill-strong` | 强调色**填充**面（选中项底、标题栏按钮悬停） |
| `accent-faint` / `accent-soft` | 强调色的极淡/淡色洗：**悬停一律用 `accent-soft`**（`accent-faint` 在白面上只有四级的差，等于没有反馈），`accent-faint` 只留给淡边框 |
| `subtle` / `on-accent-hover` / `on-accent-pressed` | **不是调色板角色，是生成器派生的洗**：白（亮色下黑）的固定透明度，铺在说不出名字的面上——侧边页签没东西可标时的占位条、强调色块上按钮的两态。派生而不手填，是为了和 `DockStyleColors::fromPalette()` 在运行时算出的同一个答案一致 |
| `highlight` | 提示性黄（下拉框悬停边） |
| `close-hover` / `close-pressed` | 关闭按钮悬停/按下（微软系红，通常不改） |

## 门禁（写文件之前自动跑）

`build_themes.py` 先过三道检查，有任何一条不过就整体退出、一个文件都不写。
改色板改出问题，在这里就会报出来，而不是等所有样式表都生成完：

| 检查 | 判据 |
| :--- | :--- |
| 对比度 | 每条规则的「字 on 填充」要够 WCAG AA 的 4.5:1（这些样式表画的是 12–13px 小字，不吃大字 3:1 的宽待）；渐变逐色标取最差。字色按「本条声明 → 所属常态规则 → 调色板 `text`」继承——平台在样式表沉默时画的就是 `text`。`:disabled` 豁免，它本来就该退后 |
| 状态 | 常态填充用**状态色**（`state-*`）的规则，`:hover` / `:selected` / `:checked` 必须换一个填充；常态用面色（`surface*` / `border` / `body`）的可以只靠边——输入框悬停只变边是正常设计。两者都不画填充的（页签悬停只加下划线）不管 |
| 选中 | `::item:selected` 的填充不能和所在视图的填充一样，否则选中行在视图里找不到 |

两处猜不到的地方写死在脚本里，也有注释说明：标题栏窗口按钮的字形是 C++ 按调色板
角色染的（`windowbuttongroup.cpp`：关闭键悬停/按下用 `HighlightedText`，其余用
`WindowText`），样式表选不了那个色，所以这些填充按 WCAG 非文字的 3:1 校；规则不画
填充时门禁什么都不查——它不知道控件后面坐着谁。

## 三条约定

1. **样式表里不写图标**。Ribbon 的箭头、窗口按钮、对话框启动器都是单色掩膜，
   颜色由 `QPalette` 决定（`qxribbon` 用 `QxRibbon::tintedIcon()` 画），换主题时自动重绘。
   样式表能做的只有**去掉**一个形状，不是换成另一张图：`::menu-indicator` 里的 `image:` 是
   原样贴上去的、不跟调色板，所以快速访问栏那个平台三角是靠 `QxRibbon--RibbonQuickAccessBar
   QToolButton::menu-indicator { image: none }` 删掉的，不是换成小箭头。
2. 调色板只由**明暗**决定（`QxTheme::paletteFor(bool)`），所以一个家族只要给对
   `dark` 就不用碰库；样式表负责"这套设计语言长什么样"，调色板负责"没被样式表
   描述到的控件取什么色"。
3. **浅色主题的 `:pressed` 不填实色**。浅色的文字和字形都是深色（图标按 `text` 上色），
   填 `accent-fill` 就成了「深色压在中间蓝上」，既不是看得清的字，也不是看得清的图。
   按下态用比 hover 深一档的浅色填充 + `accent` 描边；实色填充只留给内容本身是
   浅色的地方（应用按钮、gallery 选中项）。暗色正相反 —— 那里的字形本来就是浅色。
   这条不是约定而是门禁：对比度检查会把它拦下来，生成直接失败、一个文件都不写。
